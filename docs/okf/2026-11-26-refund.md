# 목표
매장취소 · 고객취소(자동 취소 포함) 주문의 환불이 끝나면 서버가 바꿔 주는 「환불」 상태를 주문내역 · 영수증에 규칙대로 보인다.[^spec]

# 작업 내용
- 주문 상태에 「환불」(`refunded`, 가정)을 더했다. 서버가 바꿔 알려 주는 상태라 매장 프로그램이 보내는 요청은 없다.
- 「취소된 주문」 판단을 `isCancelledStatus`(`src/shared/api/orders.ts`) 하나로 모으고 환불을 넣었다. 주문접수 화면 · 위젯 · 5초 배너 · 처리할 주문 조회에서 환불이 빠진다.
- 주문내역: 「취소」 탭에 「환불」(빨강), 전체 합계에서 빼고 「(취소 N건 제외)」에 센다, 취소 탭 합계에 넣는다. 상세 처리 이력에 취소 줄 다음 「환불 시각」. 버튼은 [영수증 인쇄]만, 영수증은 취소 영수증.
- 「N번째 주문」에서 취소 · 환불을 뺀다. 모의 서버도 가짜값 대신 같은 고객의 앞선 주문을 실제로 센다(모의 한 달만).
- 개발용 모의 패널에 [가장 최근 취소 → 환불 완료]를 더하고, 지난 날 모의 주문에 환불을 섞었다.

# 작업 방법
- 진행: 지휘 세션 pos-boss / 작업 세션 t22-refund-45 (Sonnet 5.5), 워크트리 `~/.whale-smart-pos-worktrees/T22-refund`, 브랜치 `feature/WHALEERPPO-55-refund`
- 접근: 여러 곳에 흩어진 「매장취소 || 고객취소」 비교를 타입 가드 하나로 모아 환불을 한 곳에서 더했다. 고객취소만 골라야 하는 3곳(고객취소 배너 판단 등)은 그대로 둔다.
- 환불 시각은 목록용 `Order`가 아니라 상세의 `CancelInfo.refundedAt`(가정)에 둔다. 환불은 늘 취소 뒤에 오고 목록용 주문에는 취소 정보가 없기 때문이다(지시서와 다르게 했고 리뷰어도 맞다고 봄).
