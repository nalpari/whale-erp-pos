# 구현 계획: 공통 로그 · 오류 기록 (`logging`, T14)

- **스펙**: `docs/specs/SPEC-logging.md` (2026-11-17 승인)
- **Plane**: WHALEERPPO-15. Plane에는 태스크(T14) 하나만 두고, 아래 단계는 이 문서의 체크리스트로 관리한다.
- **선행**: T00 · T01 · T02 · T11이 `main`에 있다 (완료).
- **상태**: 승인 (2026-11-17, 사용자 "A-1"로 스펙과 함께)

## 개요

Tauri 공식 로그 플러그인으로 화면 · Rust의 오류와 주요 사건을 PC 파일에 남기고, 더보기 메뉴에 "로그 확인" 화면(경로 · 폴더 열기 · 최근 200줄)을 더한다.

## 단계

### 0단계. 플러그인 확인 보고 (코드 없음, 맨 앞)

- 완료 기준
  - [ ] `tauri-plugin-log` · `@tauri-apps/plugin-log` · `log` 버전, 설치 방법, 권한(`log:default`)을 공식 문서로 확인
  - [ ] `RotationStrategy::KeepSome(n)`에서 실제로 몇 개 파일이 남는지(현재 파일 포함 여부)와 현재 파일 이름을 확인
  - [ ] pos-boss에 보고하고 승인을 기다림. 기다리는 동안 라이브러리 없이 할 수 있는 일(로그 문장 만들기 · 개인정보 검사, 로그 화면 UI를 가짜 데이터로)을 진행
- 크기: XS

### 1단계. 로그 남기기 (0단계 승인 뒤)

- 완료 기준
  - [ ] 플러그인 등록: info 이상, 5MB, KeepSome, 한국 시간 (스펙 2.2)
  - [ ] 화면 `console.warn` · `console.error`를 로그로 보냄, Rust `eprintln`을 `log` 매크로로 (스펙 2.3)
  - [ ] 주요 사건 6가지 로그, 개인정보 없음 테스트 (스펙 2.3, 2.4)
- 검증: 단위 테스트, `cargo test`, Linux `pnpm tauri dev`에서 로그 파일 생성 확인
- 크기: M

### 확인 지점 1

- [ ] ① 통과, 중간 보고 (로그 파일 위치와 예시 몇 줄 포함. 개인정보 없는지 pos-boss가 직접 봄)

## 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 로그에 개인정보가 섞임 | 상 | 주요 사건은 정해진 함수로만 남기고, 개인정보 입력 테스트로 막는다. console.error로 들어오는 오류 객체는 요약해서 남긴다 |
| 로그 폴더 열기 명령이 OS마다 다름 | 낮음 | Windows · Linux · macOS 분기, Windows는 체크리스트로 확인 |
| 5MB 회전을 Linux에서 빨리 확인하기 어려움 | 낮음 | 테스트에서는 작은 크기로 확인하는 방법을 작업 세션이 제안 |

- 단계 순서: 0(보고) → 1 → (확인 지점 1) → 2 → (확인 지점 2).
