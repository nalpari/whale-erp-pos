# 구현 계획: 로그인 · 점포번호 찾기 (`login`, T02)

- **스펙**: `docs/specs/SPEC-login.md` (2026-11-16 승인)
- **Plane**: WHALEERPPO-3. Plane에는 태스크(T02) 하나만 두고, 아래 단계는 이 문서의 체크리스트로 관리한다.
- **선행**: T01이 `main`에 들어온 뒤 시작한다.
- **상태**: 승인 (2026-11-16, 사용자)

## 개요

T01의 모의 로그인 상태를 실제 로그인 흐름으로 바꾼다. 점포번호 · 마스터 로그인, 권한(`canEditSettings`), 점포번호 찾기, 자동 로그인을 만든다. 서버는 `AuthApi` 모의 구현이다.

## 구조 결정

- `AuthApi` 인터페이스 뒤에 모의 구현을 둔다. 시험용 계정은 코드 상수로 두고 "모의 데이터"라고 주석을 단다 (스펙 5장).
- 로그인 상태와 권한은 `src/shared/session/`에 두고 T01의 모의 상태를 대체한다.
- 자동 로그인 토큰은 Windows 보안 저장소에 둔다. 쓸 플러그인은 0단계에서 조사해 승인받는다 (스펙 4장).
- 휴대폰 번호는 어디에도 저장 · 기록하지 않는다 (스펙 8장).

## 단계

### 0단계. 보안 저장소 플러그인 조사 (코드 없음, 맨 앞)

승인을 기다리는 동안 다른 단계를 진행할 수 있게 먼저 보고한다.

- 완료 기준
  - [ ] Tauri v2에서 Windows 보안 저장소(자격 증명 관리자 등)를 쓰는 공식 · 대표 방법 1~2개를 공식 문서로 확인
  - [ ] 각각의 장단점, 추가되는 라이브러리, Linux 개발 환경에서의 동작을 pos-boss에 보고하고 승인을 기다림
- 크기: XS

### 1단계. 로그인 상태와 권한

- 완료 기준
  - [ ] `AuthApi` 인터페이스 + 모의 구현 (스펙 5장)
  - [ ] 세션 상태와 `canEditSettings` (점포번호 거짓, 마스터 참) (스펙 9장 2)
  - [ ] T01의 모의 로그인 상태를 이 세션 상태로 바꿔도 T01 테스트가 통과
- 검증: 단위 테스트, T01 테스트
- 파일(예상): `src/shared/api/auth.ts`, `src/shared/session/`, `src/app/`, 테스트
- 크기: M

### 2단계. 점포 번호로 로그인

- 완료 기준
  - [ ] 입력 칸 2개, 휴대폰 번호는 숫자만 (붙여 넣기 포함), 눈 아이콘, 두 칸이 차야 버튼 활성, Enter 로그인 (스펙 3.1)
  - [ ] 실패 문구 "! 아이디와 비밀번호가 올바르지 않습니다.", 입력을 고치면 지움. 네트워크 오류는 "서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요." (스펙 3.1, 10장)
  - [ ] 성공하면 주문접수 탭과 점포명이 보임 (스펙 3.4)
- 검증: 화면 테스트
- 파일(예상): `src/features/login/`, 테스트
- 크기: M

### 3단계. 마스터 계정 탭

- 완료 기준

  - [ ] 탭을 바꾸면 입력값과 오류 문구를 지움
- 검증: 화면 테스트
- 파일(예상): `src/features/login/`, 테스트
- 크기: S

### 4단계. 점포번호 찾기 팝업

- 완료 기준
  - [ ] 입력 칸 2개, 두 칸이 차야 찾기 활성, 실패 문구 두 줄 (스펙 3.3)
  - [ ] 완료 상태: 제목, "{점포명} 님의 점포번호 찾기가 완료되었습니다.", 가려진 번호, [로그인] [닫기] (스펙 3.3)
  - [ ] [로그인]은 칸을 비운 채 점포 번호 탭으로, [닫기] · [취소] · ×는 팝업 닫기 (스펙 3.3, 9장 5)
- 검증: 화면 테스트
- 파일(예상): `src/features/login/` 팝업, 테스트

- 검증: 단위 테스트, Windows 확인 체크리스트(재실행 뒤 자동 로그인)

## 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 보안 저장소 플러그인이 Linux 개발 환경에서 동작하지 않음 | 중 | 감싸기 모듈 뒤에 두고 개발 · 테스트는 메모리 구현. Windows에서 확인 |
| 실제 로그인 API 모양이 가정과 다름 | 중 | 인터페이스 뒤에 모의 구현을 둬서 바꿀 곳을 한 곳으로 모음. 백엔드 협의 결과가 오면 스펙부터 고침 |
| 기획자 답(Q09, Q12)으로 화면 흐름이 바뀜 | 낮음~중 | 임시 처리라고 스펙에 표시했고, 답이 오면 스펙 → 계획 순서로 고침 |
