# 테스트 시나리오: T19 도착 예정 시각

- **태스크**: T19 도착 예정 시각 (Plane WHALEERPPO-52)
- **스펙**: `docs/specs/SPEC-order-board.md` 12장, `docs/specs/SPEC-print-forms.md` 12장
- **환경**: Linux 개발 PC. 화면 흐름은 브라우저(`pnpm dev`, http://localhost:1420), 위젯 · 출력은 `GDK_BACKEND=x11 pnpm tauri dev`, 모의 서버
- **처음 작성**: 2026-11-27
- **확인하지 못하는 것**: 실물 프린터 출력, 실제 터치스크린, Windows. 브라우저에서는 위젯 창과 프린터 설정(Tauri 전용)이 동작하지 않는다. 「N분 지남」 빨간 글자는 실제로 기다려야 보여서 가짜 시계 테스트로 확인했다
- **분 경계 (테스트로 고정)**: 남은 분은 올림(「0분 뒤」 없음). 도착 정각부터 1분 미만은 괄호 없이 「HH:mm 도착」. 1분 이상 지나면 내림으로 「N분 지남」(빨강)

## 준비

| 순서 | 할 일 |
|---|---|
| P1 | 점포번호 탭에서 `ST000001` / `1234`로 로그인 (모의 계정) |
| P2 | 헤더의 주문받기를 ON. 환경설정 > 주문설정의 도착 최소 시간은 기본 5분 |
| P3 | 화면 왼쪽 아래 「개발용 모의 주문」을 열고 [주문 1건]을 2번 누른다 (도착 = 결제 + 5분, + 10분) |

## A. 화면 문구

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| A1 | [주문접수] 탭에서 두 카드의 시간 줄을 봄 | 「HH:mm 도착 (5분 뒤)」 · 「HH:mm 도착 (10분 뒤)」. 1분마다 괄호 안 숫자가 1씩 준다 | 통과 (2026-11-27, 브라우저 · pos-boss) |
| A2 | 첫 카드를 눌러 요약 팝업을 엶 | 기본 정보 항목 이름이 「도착 예정」, 값은 카드와 같은 「HH:mm 도착 (5분 뒤)」 | 통과 (2026-11-27, 브라우저 · pos-boss) |
| A3 | [주문내역] → 주문 하나 상세 | 항목 이름 「도착 예정」, 값은 괄호 없이 「HH:mm 도착」 | 통과 (2026-11-27, 브라우저 · pos-boss) |
| A4 | 첫 주문의 도착 시각에서 1분 넘게 기다림 | 카드 · 요약 팝업 괄호 안이 빨간 「1분 지남」. 정각부터 1분 전까지는 괄호가 없다 | 실제 창 확인 안 함 · 가짜 시계 테스트로 확인 |

## B. 위젯 · 출력 (Tauri 앱에서만)

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| B1 | 바탕화면 위젯을 띄움 | 카드 시간 줄이 「주문시간 HH:mm \| HH:mm 도착 (N분 뒤)」, 지나면 빨간 「N분 지남」 | 실제 창 확인 안 함 · 자동 테스트로 확인 (실물은 Windows 체크 때) |
| B2 | 프린터설정에서 주문서 프린터를 정한 뒤 주문 접수 → 개발용 [출력 미리보기] | 주문서 정보 줄이 「도착예정: HH:mm」 (「픽업예정」 · 「지금」 없음) | 실제 창 확인 안 함 · 자동 테스트로 확인 (실물은 Windows 체크 때) |
| B3 | 주문내역 상세 [영수증 인쇄] 미리보기, 취소한 주문의 영수증 미리보기 | 「주문번호: …」 바로 다음 줄에 「도착예정: HH:mm」. 취소 영수증은 원 주문의 값 | 실제 창 확인 안 함 · 자동 테스트로 확인 (실물은 Windows 체크 때) |
