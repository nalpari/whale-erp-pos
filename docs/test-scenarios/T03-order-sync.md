# 테스트 시나리오: T03 주문 수신 · 상태 동기화

- **태스크**: T03 주문 수신 · 상태 동기화 (Plane WHALEERPPO-4)
- **스펙**: `docs/specs/SPEC-order-sync.md`
- **환경**: Linux 개발 PC, `GDK_BACKEND=x11 pnpm tauri dev`, 모의 서버
- **처음 작성**: 2026-11-26 (지난 태스크 소급 작성, main 코드 기준)
- **이전 확인**: OKF 「검증」의 Linux 실제 창 확인 순서 1~6 (모의 버튼으로, 2026-11-18). 결과 기록은 OKF에 따로 없다.
- **확인하지 못하는 것**: 실제 서버 · 실시간 전달 방식(백엔드 미정), 경고음 · 알림음 크기(사람이 귀로 판단), 다시시작 뒤 첫 조회에서 새 주문 알림이 안 나는 것(모의 서버가 다시 켜면 비어서 테스트로만 확인), 30초 재조회 · 시간 초과 뒤 재확인(테스트로만 확인), 설치 파일에 모의 패널이 없는 것(Windows 체크리스트)

## 준비

| 순서 | 할 일 |
|---|---|
| P1 | 「점포번호로 로그인」 탭에서 점포코드 `ST000001`, 비밀번호 `1234`로 로그인 (모의 계정) |
| P2 | 화면 왼쪽 아래 「개발용 모의 주문」을 펼친다 |

## A. 수신 · 처리할 주문 건수

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| A1 | [주문 10건] | [주문접수] 탭에 접수대기 카드 10장, 필터 「접수대기 10」 | |
| A2 | 헤더 더보기(⋮) → [프로그램 종료] | 확인창에 「처리할 주문이 10건 있습니다. 프로그램을 끄면 이 주문을 처리하거나 고객에게 알림을 보낼 수 없습니다.」. [취소]로 닫는다 | |
| A3 | 더보기 맨 앞 [새로고침] | 로그인 · 주문받기 ON/OFF · 카드 10장이 그대로 | |

## C. 연결 끊김

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| C1 | 헤더 「주문 받기」를 ON으로 둔 뒤 [연결 끊기] | 몇십 초 안에 헤더 아래 빨간 띠 「인터넷 연결이 끊겼습니다. 새 주문을 받을 수 없습니다. 다시 연결하는 중…」, 경고음 한 번. 띠에 닫기 버튼이 없다 | |
| C2 | 끊긴 채로 카드 하나의 [주문접수] | 토스트 「#N 처리하지 못했습니다. 잠시 뒤 다시 시도해 주세요.」, 카드는 접수대기 그대로 | |
| C3 | 끊긴 채로 [주문 1건] → [연결 잇기] | 몇 초 뒤 띠가 사라지고, 끊긴 사이 만든 주문이 들어온다. 「주문 받기」는 끊기기 전 값(ON)으로 돌아온다 | |
