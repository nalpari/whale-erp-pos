# 테스트 시나리오: T08 매장정보

- **태스크**: T08 매장정보 (Plane WHALEERPPO-9)
- **스펙**: `docs/specs/SPEC-store-info.md`
- **환경**: Linux 개발 PC, `GDK_BACKEND=x11 pnpm tauri dev`, 모의 서버
- **처음 작성**: 2026-11-26 (지난 태스크 소급 작성, main 코드 기준)
- **이전 확인**: 2026-11-19 사용자가 머지 뒤 Linux 실제 창에서 확인 순서 1~7을 확인, 정상 (OKF `docs/okf/2026-11-19-store-info.md`)
- **확인하지 못하는 것**: 불러오기 · 저장 실패(모의 서버를 화면에서 실패시킬 수 없어 테스트로만 확인), Windows WebView2 한글 입력기에서 한도 근처 입력, 화상 키보드, 1024 × 768 화면. 모의 서버라 앱을 다시 켜면 값이 처음으로 돌아간다

## 준비

| 순서 | 할 일 |
|---|---|
| P1 | 점포번호 탭에서 점포코드 `ST000001`, 비밀번호 `1234`로 로그인 (모의 계정) |
| P2 | 매장정보 탭을 연다. 모의 서버가 소개 「갓 내린 커피와 수제 디저트를 파는 동네 카페입니다.」, 공지 「매주 월요일은 쉽니다.」, 편의시설 4묶음(결제수단 · 편의 · 동반 · 운영)을 준다 |

## A. 화면 · 입력 제한

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| A1 | 화면을 본다 | 맨 위 안내 「매장정보는 픽업오더 앱에 표시됩니다. …」, 「점포 소개」 · 「점포 공지」 · 「편의시설 및 서비스」, 칸마다 「N / 100자」 · 「N / 200자」. [저장]은 막혀 있다 | |
| A2 | 점포 소개를 모두 지운다 | 「점포 소개를 입력해 주세요.」, [저장] 막힘 | |
| A3 | 점포 소개에서 Enter로 넷째 줄을 만든다 | 줄이 더 생기지 않고 「3줄까지 입력할 수 있습니다.」 | |
| A4 | 점포 소개 가운데에 긴 글을 붙여 넣어 100자를 넘긴다 | 원래 글은 그대로, 붙여 넣은 부분만 잘려 100자가 된다. 「100자까지 입력할 수 있습니다.」 | |
| A5 | 점포 공지에서 여섯째 줄 · 200자 넘기기를 해 본다 | 「5줄까지 입력할 수 있습니다.」 · 「200자까지 입력할 수 있습니다.」, 원래 글은 지워지지 않는다 | |
| A6 | 한글을 조합하는 중(받침 전)에 한도에 닿게 친다 | 조합 중 글자가 깨지지 않는다 | |

## B. 저장

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| B1 | 소개 한 글자를 고치고 [저장] | 「저장되었습니다」, [저장]이 다시 막힌다 | |
| B2 | 공지의 「앱에 표시」 스위치를 끈다 | 글자가 「표시 안 함」으로 바뀌고 [저장]이 켜진다 | |
| B3 | 편의시설에서 「주차」 체크를 바꾸고 [저장] | 「저장되었습니다」 | |
| B4 | 공지를 모두 비우고 태그를 모두 풀고 [저장] | 막지 않고 저장된다 | |
| B5 | 주문접수 탭에 갔다가 다시 매장정보 탭 | B1~B4에서 저장한 값이 그대로 | |

## C. 저장하지 않고 떠나기

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| C1 | 소개를 고치고 저장하지 않은 채 주문내역 탭을 누른다 | 확인창 「저장하지 않은 내용이 있습니다.」 「나가면 고친 내용이 사라집니다. 나가시겠습니까?」 [취소] [나가기] | |
| C2 | [취소] | 매장정보에 남고 고친 글도 그대로 | |
| C3 | 다시 주문내역 탭 → [나가기] → 매장정보 탭으로 돌아온다 | 주문내역으로 이동했고, 돌아오면 고친 글은 사라지고 저장된 값이 보인다 | |
| C4 | 소개를 고친 채 바탕화면 위젯의 주문 카드를 눌러 주문접수로 간다 (「개발용 모의 주문」 [주문 1건]으로 위젯을 띄움) | 확인창 없이 주문접수 화면으로 바로 가고 그 주문의 요약 팝업이 열린다. 매장정보 탭으로 돌아오면 고친 내용은 버려져 있다 | |
