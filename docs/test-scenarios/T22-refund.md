# T22 「환불」 표시 — 실제 창 테스트 시나리오

- **태스크**: T22 (Plane WHALEERPPO-55), 스펙 `docs/specs/SPEC-order-history.md` 12.1
- **환경**: Linux 개발 PC, 모의 서버

## 확인하지 못하는 것

- 실물 프린터의 취소 영수증 모양 · 커팅 (개발 출력 미리보기로만 본다)
- 실제 서버가 보내는 취소 · 환불 사건 순서. 접수대기에서 바로 「환불」로 오면 고객취소 배너가 안 나온다(백엔드 협의 항목)

| 항목 | 내용 |

| 영수증 (B-2) | 환경설정 탭 → [프린터설정]에서 「영수증」이 체크된 프린터가 있어야 미리보기가 나온다 |

## A. 매장취소 → 환불

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| A-1 | [주문 1건]을 두 번 누른다 | 주문접수 화면에 #1, #2 접수대기 카드 | 통과 |
| A-2 | #1 카드 → [주문취소] → 「재료가 소진되었습니다」 → [주문취소] | #1 카드가 사라진다 | 통과 |
| A-3 | [가장 최근 취소 → 환불 완료] | 주문접수 화면 · 위젯 · 픽업완료 탭 어디에도 #1이 없다. 알림음 · 배너 없음 | 통과 |

## B. 주문내역

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| B-1 | 주문내역 탭 → 오늘 → 「취소」 탭 | #1 행 상태가 빨간 「환불」, 요약의 취소 금액에 #1 금액이 들어 있다 | 통과 |
| B-2 | 「전체」 탭 | 요약 「(취소 1건 제외)」, 결제 합계에 #1 금액이 없다 | 통과 |
| B-3 | #1 행을 연다 | 제목 「#1 환불」(빨강). 처리 이력 끝 두 줄: 「매장취소 시각 재료가 소진되었습니다」, 「환불 시각」. 버튼은 [영수증 인쇄]만 | 통과 |
| B-4 | [영수증 인쇄] | 미리보기 제목 「취소 영수증」, 금액이 모두 마이너스 | |
| B-5 | #2 상세 | 기본 정보가 「첫 주문」(앞선 #1이 환불이라 빠짐) | 통과 |

## C. 고객취소 → 환불, 지난 날

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| C-1 | [고객 취소(가장 오래된 접수대기)] | #2가 고객취소, 고객취소 배너 · 알림음 (기존 동작) | |
| C-2 | 바로 [가장 최근 취소 → 환불 완료] | 취소 탭에 #2도 「환불」, 상세 처리 이력 「고객취소 시각」 다음 「환불 시각」 | |
