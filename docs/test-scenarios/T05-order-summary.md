# 테스트 시나리오: T05 요약 · 취소 팝업

- **태스크**: T05 요약 · 취소 팝업 (Plane WHALEERPPO-6)
- **스펙**: `docs/specs/SPEC-order-summary.md`
- **환경**: Linux 개발 PC, `GDK_BACKEND=x11 pnpm tauri dev`, 모의 서버
- **처음 작성**: 2026-11-26 (지난 태스크 소급 작성, main 코드 기준)
- **이전 확인**: 지휘 세션이 `pnpm tauri dev`로 켜고 사용자가 확인 순서 1~5대로 확인, 정상 (2026-11-19, OKF 「검증」)
- **확인하지 못하는 것**: 실제 터치 · 팝업 안 손가락 스크롤, Windows 한글 입력기에서 50자 근처 조합, 인쇄 버튼 동작(`T12-print-forms.md`에서 확인)
- 제조완료 · 픽업완료 주문의 [주문취소]는 `T18-cancel-scope.md`, [재제조]는 `T21-remake.md`를 본다.

## 준비

| 순서 | 할 일 |
|---|---|
| P1 | 「점포번호로 로그인」 탭에서 점포코드 `ST000001`, 비밀번호 `1234`로 로그인 (모의 계정) |
| P2 | 화면 왼쪽 아래 「개발용 모의 주문」을 펼치고 [주문 10건] |

## A. 요약 팝업

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| A1 | #3 카드의 버튼 밖을 누른다 | 요약 팝업. 처리 단계 접수대기 → 제조중 → 제조완료 → 픽업완료(접수대기 강조), 주문일시 · 16자리 주문번호 · 도착 예정(「HH:mm 도착 (N분 뒤)」, T19) · 고객명 「홍*동」 · 연락처 「***-****-0000」, 요청사항, 메뉴 5개 전체(옵션은 쉼표 한 줄) | |
| A2 | 버튼을 본다 | [주문취소] [주문접수(파란색)]. [영수증 인쇄] [주문서 인쇄]도 보인다(접수대기라 [주문서 인쇄]는 막힘, 인쇄 동작은 `T12-print-forms.md`) | |
| A3 | [닫기](×) / 바깥 영역 / Esc로 각각 닫기 | 셋 다 닫힌다 | |
| A4 | 다시 열고 [주문접수] → [제조완료] | 팝업이 열린 채 단계가 넘어가고 지난 단계에 체크 + 시:분. 버튼이 [주문취소] [제조완료] → [주문취소] [재제조] [픽업완료]로 바뀐다 | |
| A5 | [픽업완료] | 팝업이 닫히고 화면 아래 픽업완료 배너 5초 | |
| A6 | 「픽업완료」 탭에서 그 카드를 연다 | 네 단계 모두 체크 + 시각 | |

## B. 주문취소 팝업

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| B1 | 접수대기 카드 열기 → [주문취소] | 「주문을 취소하시겠습니까?」, 사유 4개 + 「직접 입력」. 아무것도 안 골라 [주문취소]가 막혀 있다 | |
| B2 | 「직접 입력」을 고르고 50자가 넘는 글을 붙여 넣는다 | 50자에서 잘리고 「50자까지 입력할 수 있습니다.」 | |
| B3 | 「재료가 소진되었습니다」로 [주문취소] | 두 팝업이 닫히고 카드가 사라진다 | |
| B4 | 제조중 카드에서 B1 · B3 | 똑같이 취소된다 | |

## C. 열린 동안 바뀌는 경우

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| C1 | 가장 오래된 접수대기 카드 팝업을 열어 둔 채 개발 패널 [다른 PC가 접수] | 팝업이 열린 채 「제조중」으로 바뀐다 | |
