# 테스트 시나리오: T09 메뉴품절

- **태스크**: T09 메뉴품절 · 품절상품 추가 팝업 (Plane WHALEERPPO-10)
- **스펙**: `docs/specs/SPEC-soldout.md`
- **환경**: Linux 개발 PC, `GDK_BACKEND=x11 pnpm tauri dev`, 모의 서버
- **처음 작성**: 2026-11-26 (지난 태스크 소급 작성, main 코드 기준)
- **이전 확인**: 2026-11-19 사용자가 머지 뒤 Linux 실제 창에서 확인 순서 1~7, 검색 추가 · 검색 줄 배치 변경 뒤 다시 확인, 정상 (OKF `docs/okf/2026-11-19-soldout.md`)
- **확인하지 못하는 것**: 저장 · 삭제 · 추가 실패와 되돌림(모의 서버를 화면에서 실패시킬 수 없어 테스트로만 확인), 다른 곳에서 먼저 등록돼 일부만 추가되는 경우, 웨일ERP에서 바꾼 품절이 보이는지(실서버 연결 뒤), 실제 터치스크린 · 화상 키보드, 1024 × 768 화면. 모의 서버라 앱을 다시 켜면 처음 값으로 돌아간다

## 준비

| 순서 | 할 일 |
|---|---|
| P1 | 점포번호 탭에서 점포코드 `ST000001`, 비밀번호 `1234`로 로그인 (모의 계정). 메뉴품절은 두 계정 모두 바꿀 수 있다 |
| P2 | 메뉴품절 탭을 연다. 모의 서버의 처음 품절은 「아메리카노」(일시품절) · 「치즈케이크」(숨김) · 「샷 추가」(옵션, 일시품절) 세 개다 |

## D. 품절 상품 추가 팝업

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| D1 | [+ 품절 상품 추가] | 팝업 「품절 상품 추가」. 탭 [전체] · 커피 · 논커피 · 티 · 디저트 · [옵션]. 이미 품절인 「아메리카노」 · 「치즈케이크」는 회색 「등록됨」, 체크가 안 된다 | |
| D2 | 「카페라떼」 체크 → 「디저트」 탭으로 가서 「마들렌」 체크 → [전체] 탭 | 두 체크가 그대로, 「2개 선택됨」 | |
| D3 | [옵션] 탭에서 「두유 변경」 체크 → [추가하기] | 「3개를 일시품절로 추가했습니다.」. 팝업은 열린 채 세 항목이 「등록됨」으로 바뀐다 | |
| D4 | 팝업 검색칸에 `라떼` | 이름에 「라떼」가 들어간 상품만 | |
| D5 | [닫기] | 목록 맨 위에 D3의 세 항목이 일시품절로 보인다 | |
| D6 | 목록 검색칸에 `케이크`를 둔 채 팝업에서 「티라미수」를 추가하고 닫는다 | 목록 검색어가 지워지고 「티라미수」가 맨 위에 보인다 | |
