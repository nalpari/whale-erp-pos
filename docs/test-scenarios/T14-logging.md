# 테스트 시나리오: T14 공통 로그 · 로그 확인

- **태스크**: T14 공통 로그 (Plane WHALEERPPO-15)
- **스펙**: `docs/specs/SPEC-logging.md`
- **환경**: Linux 개발 PC, `GDK_BACKEND=x11 pnpm tauri dev`, 모의 서버
- **처음 작성**: 2026-11-26 (지난 태스크 소급 작성, main 코드 기준)
- **이전 확인**: 2026-11-17 Linux `pnpm tauri dev`에서 `app.log`에 「앱 시작: 0.1.0」 줄이 한국 시간으로 남는 것을 지휘 세션이, [로그 확인] 화면 · 폴더 열기 · 닫기를 사용자가 확인 (`docs/okf/2026-11-17-logging.md`)
- **확인하지 못하는 것**: 5MB 회전과 보관 개수(파일을 5MB까지 채워야 한다), 잡히지 않은 오류의 `[uncaught]` 줄(일부러 오류를 내야 한다), 작업 관리자 강제 종료 때 「앱 종료」 줄이 없는 것(알려진 한계).

## 준비

| 항목 | 내용 |
|---|---|
| 실행 | `GDK_BACKEND=x11 pnpm tauri dev` |
| 로그 파일 | Linux `~/.local/share/com.whale.pickuporder.dev/logs/app.log`, Windows `C:\Users\<사용자>\AppData\Local\com.whale.pickuporder.dev\logs\app.log` |
| 로그인 | 점포번호 계정 ST000001 / 1234 |

## A. 로그 확인 화면

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| A-1 | 로그인 전에 [더보기] → [로그 확인] | 제목 「로그 확인」, 「로그 위치: …/logs」, [로그 폴더 열기] [새로고침] [닫기], 아래에 최근 로그(최대 200줄)가 맨 아래까지 스크롤된 채 보인다 | |
| A-2 | [로그 폴더 열기] | 파일 관리자가 로그 폴더를 연다 | |
| A-3 | 로그인 화면에서 점포코드 · 비밀번호를 넣은 뒤 [로그 확인] → [닫기] | 넣었던 값이 그대로 남아 있다 | |
| A-4 | 로그인한 뒤 [더보기] → [로그 확인] | 웨일ERP 계정으로 로그인해도 똑같이 열린다 | |
| A-5 | 화면을 연 채 다른 동작을 하고 [새로고침] | 새 줄이 더해진다 | |

## B. 남는 줄 · 개인정보

| ID | 동작 | 기대 결과 | 결과 |
|---|---|---|---|
| B-1 | 앱을 켠 뒤 [로그 확인] | 「앱 시작: <버전>」 줄. 시각이 한국 시간(PC 시각과 같다) | |
| B-2 | 비밀번호 `9999`로 로그인 실패 → 맞게 로그인 | 「로그인 실패: 점포번호 계정, 아이디 · 비밀번호 틀림」, 「로그인 성공: 점포번호 계정」 | |
| B-3 | 웨일ERP 계정(`master-demo` / `demo1234!` / `ST000001`)으로 로그인 | 「로그인 성공: 웨일ERP 계정」 | |
| B-4 | 주문받기 ON → OFF([주문 중단]) | 「주문받기 ON 요청: 성공」, 「주문받기 OFF 요청: 성공」 | |
| B-5 | 환경설정 탭 → [프린터설정]에서 프린터를 등록하고 [시험 인쇄] | 「시험 인쇄: <프린터 이름>, 성공」 | |
| B-6 | [로그아웃] / [프로그램 종료] 뒤 `app.log`를 연다 | 「로그아웃」, 「앱 종료」 줄 | |
| B-7 | 자동로그인 체크로 로그인 → 종료 → 다시 켠다 | 「자동 로그인 재개: 성공」 | |
| B-8 | B-2~B-7 뒤 `app.log` 전체에서 점포코드 `ST000001`, 비밀번호 `1234` · `demo1234!`, 아이디 `master-demo`, 토큰 값을 찾는다 | 하나도 없다 | |
