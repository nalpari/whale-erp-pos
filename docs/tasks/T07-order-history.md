# T07. 주문내역 · 주문내역 상세

- **출처**: 화면정의서 v0.8 p.13(주문내역), p.14(주문내역 상세)
- **선행 태스크**: T01, T03 (상태 변경 버튼), T12 (인쇄 버튼)
- **크기(추정)**: 중
- **관련 문의**: Q17, Q29, Q34, Q35, Q36, Q37

## 목표

기간을 정해 지난 주문을 찾아보고, 한 건의 결제 정보와 처리 이력까지 확인한다.

## 주문내역 (p.13)

- 조회 범위: 오늘, 어제, 이번 달. 이번 달보다 앞선 내역은 ERP 웹에서 조회한다.
- 고객이 취소한 건은 보이지 않고, 매장이 거부한 건은 보인다.

| 번호 | 요소 | 내용 |
|---|---|---|
| 1 | 검색 | 픽업번호 또는 고객명 |
| 2 | 기간 선택 | 달력에서 하루 또는 기간을 고르고 [확인]. 기간 옆에 `<` `>` |
| 3 | 상태 탭 | 전체 / 접수대기 / 제조중 / 제조완료 / 픽업완료 / 주문거부. 탭마다 건수 |
| - | 요약 줄 | "총 9건 · 기간 합계 ₩27,400" |
| 4 | 주문 목록 | 픽업번호, 고객, 메뉴("아메리카노 외 2개"), 금액, 상태, 주문일시 |
| 5 | 행 클릭 | 주문내역 상세로 이동 |
| 6 | 페이지 | 페이지당 건수 선택(기본 50건), 번호·이전·다음 |
| 7 | 정렬 | 주문일시가 최근인 것이 위 |

- 접수대기 행은 배경색으로 강조한다.
- 상태 글자색: 제조중 파랑, 주문거부 빨강, 제조완료 초록, 픽업완료 검정.

## 주문내역 상세 (p.14)

| 번호 | 영역 | 내용 |
|---|---|---|
| 1 | 헤더 | [← 이전], 주문 상태, 픽업번호 |
| 2 | 주문 메뉴 | 메뉴명, 단가, 수량, 금액. 옵션은 아래에 들여쓰기. 합계 |
| 3 | 기본 정보 | 주문일시, 주문번호, 고객명(가림), 연락처(가림), 픽업예정, 주문횟수 |
| 4 | 요청사항 | 있으면 노란 강조, 없으면 빈칸 |
| 5 | 결제정보 | 주문금액, 포인트할인, 결제금액, 결제수단, 결제시각, 거래번호 |
| 6 | 처리 이력 | 주문접수·제조시작·제조완료·픽업완료 시각. 취소되면 취소 사유 글 |
| 7 | 아래 버튼 | 상태에 맞는 버튼(주문취소, 주문접수, 제조완료, 픽업완료)을 파랗게 강조. [영수증 인쇄] [주문서 인쇄] |

## 필요한 데이터 · API (가정, 백엔드 협의 전)

- 기간·상태·검색어·페이지를 받는 주문 조회 API와 상태별 건수, 기간 합계.
- 결제정보(결제수단, 거래번호, 포인트 할인). 기존 요청 문서는 고객 정보 최소화를 전제로 결제 정보를 요청하지 않았다. **범위가 늘어난다.**

## 기획서에 없어서 정해야 하는 것

- 처음 열 때의 기간 (Q34), 합계 기준 (Q35), 가린 이름의 검색 방법 (Q36).
- 접수 뒤 매장이 취소한 건이 어느 탭에 들어가는지 (Q17).

## 완료 기준

- 기간·상태 탭·검색을 바꾸면 목록과 건수가 맞게 바뀐다.
- 이번 달보다 앞선 날짜는 고를 수 없다.
- 상세 화면에서 상태에 맞는 버튼만 강조되고, 인쇄 버튼이 동작한다.
