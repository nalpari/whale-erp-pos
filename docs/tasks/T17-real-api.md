# T17. 모의 서버 → 실제 API 교체

- **출처**: 화면정의서에 없음. 백엔드 협의 결과에 따른다 (`docs/requests/backend-api-request.md`)
- **선행 태스크**: 백엔드 API 협의 완료, T02
- **크기(추정)**: 중~대 (API 모양에 따라 달라짐)
- **관련 문의**: 백엔드 요청 문서 7장 (특히 7.3절 18번 매장 상태 조회, 19번 재발급 토큰 길이)

## 목표

지금 모의 구현으로 만든 서버 연동을 실제 백엔드 API로 바꾼다.

## 지금 모의 구현인 곳

- 로그인 · 점포번호 찾기 · 자동 로그인 재개: `src/shared/api/auth.ts` (`createMockAuthApi`)
- 주문받기 ON/OFF: `src/shared/api/store-status.ts` (`createMockStoreStatusApi`)
- `src/app/App.tsx`가 개발 · 배포 구분 없이 항상 모의 구현을 쓴다. 그래서 지금 설치 파일은 테스트용이다.
- 이후 태스크(T03 주문 수신, T08 · T09 · T13 등)도 모의 구현으로 먼저 만든다. 이 태스크에서 함께 바꾸거나, 각 태스크에서 바꾸는지 스펙 단계에서 정한다.

## 정해야 하는 것 (스펙 단계)

- 서버 주소 · 환경(개발 · 운영) 구분 방법.
- 토큰 만료 · 재발급 처리 (매장 PC는 며칠씩 켜져 있다, 설계 원칙 5).
- 오류 응답을 기존 오류 종류(`InvalidCredentialsError`, `SessionExpiredError` 등)로 바꾸는 규칙.

## 완료 기준

- 실제 백엔드 개발 서버로 로그인 · 자동 로그인 · 주문받기 ON/OFF가 동작한다.
- 운영 빌드에서 모의 구현이 쓰이지 않는다.
- 모의 구현은 테스트 · 개발용으로 남는다.
