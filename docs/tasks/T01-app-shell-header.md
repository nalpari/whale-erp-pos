## 목표

모든 화면이 올라갈 바탕(헤더, 탭, 콘텐츠 영역)과 창 제어, 주문받기 토글을 만든다.

## 화면 요소 (기획서 기준)

| 요소 | 내용 |
|---|---|
| 헤더 왼쪽 | 로고(P) + "픽업오더 주문접수" |
| 주문받기 토글 | 로그인 후에만 표시. ON(초록) / OFF |
| 픽업 상태 | "픽업 상태 여유▼" 선택 상자. p.12~14 그림에만 있고 설명이 없음 (Q02) |
| 헤더 오른쪽 | 로그인 전: "로그인 후 이용해주세요." / 로그인 후: 점포명 |
| 더보기(⋮) | 창 최소화, 창 줄이기, 창 늘리기, 시스템종료, 로그아웃 |
| 탭 | 주문접수, 주문내역, 매장정보, 메뉴품절, 환경설정 (로그인 후에만 표시) |
| 환경설정 하위 탭 | 위젯설정, 프린터설정, AI챗봇 인기메뉴 설정 |

## 동작 규칙

1. **로그인 전**: 안내 문구와 창 제어 버튼만 표시한다. 탭은 숨기고 콘텐츠 영역에 로그인 화면을 둔다.
2. **로그인 후**: 탭을 표시한다. 주문받기 토글의 기본값은 OFF(주문 중단)다.
3. **토글 ON**: 확인 없이 바로 적용한다. 고객 앱에 "주문 가능"으로 표시된다.
4. **토글 OFF**: 확인 팝업을 띄운다.
   - 제목 "주문 수신을 중단하시겠습니까?"
   - 본문 "주문 수신이 중단되면 고객은 앱에서 주문을 할 수 없습니다."
   - 버튼 [취소] [주문 중단]
5. **로그아웃**: 더보기 → 로그아웃 → 확인 팝업 → 로그인 화면으로 이동한다.
   - 제목 "로그아웃 하시겠습니까?" / 본문 "주문 수신이 자동으로 중단됩니다." / 버튼 [취소] [로그아웃]
6. **창 제어**

   | 버튼 | 동작 |
   |---|---|
   | 창 최소화 | 창을 닫고 작업표시줄에만 표시 |
   | 창 줄이기 | 기본 크기로 줄이고 바탕화면 정가운데에 둔다 (기본 크기 미정, Q07) |
   | 창 늘리기 | 바탕화면 전체 크기로 확대 |
   | 시스템종료 | 완전 종료. 자동 로그아웃과 주문 수신 중단. 종료 전 확인 팝업 |

   - 시스템종료 팝업: 제목 "시스템을 종료하겠습니까?" / 본문 "주문 수신이 자동으로 중단됩니다." / 버튼 [취소] [시스템 종료]

## 필요한 데이터 · API (가정, 백엔드 협의 전)

- 점포의 주문 가능 상태를 켜고 끄는 API. 현재 `docs/requests/backend-api-request.md`에 없는 항목이다.
- 픽업 상태(여유 등)를 서버에 보내는 API. 기능이 확정되면 추가한다 (Q02).
- 프로그램이 비정상 종료되거나 인터넷이 끊겼을 때 서버가 점포를 "주문 불가"로 바꾸는 방법. 기획서에 없고 백엔드와 정해야 한다.

## 기획서에 없어서 정해야 하는 것

- 재실행·자동 로그인 때 토글 상태를 이어 갈지 (Q03). 주문 누락과 직접 관련된다.
- 접수대기 주문이 남은 상태에서 OFF·로그아웃·종료를 누를 때의 처리 (Q04).
- 트레이 사용 여부 (Q05), 시스템종료의 범위 (Q06), Windows 제목 표시줄 사용 여부 (Q08).
- 인터넷 끊김·서버 오류·업데이트 안내 화면 (Q51). `AGENTS.md` 설계 원칙 5번(며칠씩 켜 둠)에 필요하다.

## 완료 기준

- 로그인 전/후에 헤더와 탭이 기획서 p.5 상태 ①②③대로 바뀐다.
- 토글 OFF, 로그아웃, 시스템종료의 확인 팝업 문구가 기획서와 같다.
- 창 최소화·줄이기·늘리기·종료가 Windows에서 동작한다.
- 탭을 눌러 5개 화면(빈 화면 포함)으로 이동한다.
