# T14. 공통 로그 · 오류 기록

- **출처**: 화면정의서에 없음. T11 ③ 리뷰 보류 사항에서 나왔다 (`docs/okf/2026-11-17-settings-printer.md` "남은 일 / 위험")
- **선행 태스크**: T00
- **크기(추정)**: 소~중
- **관련 문의**: 없음

## 목표

매장 PC에서 문제가 생겼을 때 원인을 찾을 수 있게, 화면(React)과 Rust의 오류 · 주요 사건을 PC 파일에 남긴다.

## 배경

- 지금은 `console.error`(화면)와 `eprintln`(Rust)만 쓴다. 릴리스 Windows 빌드에서는 이 출력이 어디에도 남지 않는다 (T11 ③ 보류 a).
- 매장 PC는 며칠씩 켜져 있다 (설계 원칙 5). 로그 파일이 끝없이 커지지 않게 해야 한다.

## 정해야 하는 것 (스펙 단계)

- 쓸 방법: Tauri 로그 플러그인 등 새 라이브러리가 필요할 수 있다. 공식 문서로 확인하고 사용자 승인을 받는다 (`AGENTS.md` "의존성").
- 저장 위치, 파일 크기 · 보관 기간, 남길 수준(오류만 / 주요 사건까지).
- 매장에서 로그를 받아 오는 방법 (사용자가 파일을 보내 주는지 등).

## 지켜야 하는 것

- 고객 이름 · 연락처 · 카드 정보 · 로그인 비밀번호(매장 프로그램 비밀번호 · 웨일ERP 비밀번호)를 남기지 않는다. 주문은 `orderId`로만 남긴다 (`AGENTS.md` "개인정보 · 로그").
- 기존 `src/shared/error-summary.ts`(오류 객체를 통째로 남기지 않는 요약)를 쓴다.

## 완료 기준

- 화면과 Rust의 오류가 릴리스 빌드에서도 PC 파일에 남는다.
- 로그 파일 크기가 정해진 한도를 넘지 않는다.
- 로그에 개인정보가 남지 않는다 (테스트 또는 코드 확인).
