# T04. 주문접수 화면

- **출처**: 화면정의서 v0.8 p.11
- **선행 태스크**: T01, T03
- **크기(추정)**: 대
- **관련 문의**: Q01, Q19, Q21, Q22, Q23, Q24, Q25, Q26

## 목표

들어온 주문을 카드로 보여 주고, 카드에서 접수·거부·제조완료·픽업완료를 처리한다. 점원이 가장 오래 보는 화면이다.

## 화면 요소 (기획서 기준)

| 번호 | 요소 | 내용 |
|---|---|---|
| 1 | 보기 필터 | 접수대기 / 제조중 / 제조완료 / 픽업완료 체크 상자. 기본은 전체 선택. 해제하면 그 상태 카드를 숨긴다 |
| 2 | 새로고침 | 최신 주문 목록을 수동으로 다시 받는다 |
| 3 | 주문 카드 | 픽업번호, 상태, 주문시각, 고객명(가림), 픽업예정, 메뉴 목록(옵션은 아랫줄), 요청사항 |
| 4 | [거부] [주문접수] | 접수대기 카드에만 표시 |
| 5 | [제조완료] | 제조중 카드에 표시 |
| 6 | [픽업완료] | 제조완료 카드에 표시 |
| 7 | 픽업완료 카드 | 회색. 아래 버튼 없음 |
| 8 | 픽업완료 알림 배너 | 화면 아래. "픽업번호 #{번호} 픽업완료 되었습니다." + [완료 취소(05)] |
| 9 | 이전/다음 페이지 버튼 | 오른쪽 ∧ ∨. 설명 문장이 잘려 있음 (Q23) |

## 동작 규칙

1. **정렬**: "최신 주문 왼쪽 상단 → 오른쪽 → 아래 순". p.24의 "컬럼" 표현과 충돌한다 (Q01). **확정 전에는 배치를 만들지 않는다.**
2. **요청사항**: 있으면 노란 배경으로 강조하고, 없으면 영역을 표시하지 않는다.
3. **메뉴가 많을 때**: "+ 외 N개"로 접는다 (기준 줄 수 미정, Q24).
4. **노출 제외**: 매장이 거부한 주문과 고객이 취소한 주문은 카드를 보이지 않는다.
5. **주문접수**: 제조중으로 바꾸고 주문서를 자동 출력한다 (T12).
6. **거부**: 주문거부 사유 입력 팝업을 연다 (T05).
7. **제조완료**: 제조완료로 바꾼다.
8. **픽업완료**: 픽업완료로 바꾸고 배너를 띄운다. [완료 취소]를 누르면 픽업완료를 되돌린다.
9. **카드 클릭**: 주문 요약 팝업을 연다 (T05).
10. **카드 색**: 접수대기 노랑, 제조중 파랑, 제조완료 초록, 픽업완료 회색 (그림 기준).

## 필요한 데이터 (가정)

- 주문: 픽업번호, 상태, 주문시각, 고객명(가린 값), 픽업예정, 메뉴·옵션·수량, 요청사항.
- 고객 정보는 화면에 필요한 가린 값만 받는다 (고객 정보 최소화 원칙).

## 기획서에 없어서 정해야 하는 것

- 주문이 몰릴 때 접수대기 주문이 다음 페이지로 밀리지 않게 하는 방법 (Q01, `AGENTS.md` 설계 원칙 3번).
- 픽업완료 카드를 언제까지 보여 줄지 (Q21).
- 고객이 취소한 주문이 사라질 때 점원에게 알릴지 (Q19).
- 픽업예정 표기가 시간에 따라 바뀌는지 (Q26).

## 완료 기준

- 4개 상태의 카드가 기획서 그림대로 보이고 버튼이 상태에 맞게 나온다.
- 필터를 끄면 해당 상태 카드가 사라진다.
- 접수 → 제조완료 → 픽업완료가 버튼 한 번씩으로 진행된다.
- 주문 50건이 한꺼번에 들어와도 화면이 멈추지 않는다 (모의 서버 기준).
