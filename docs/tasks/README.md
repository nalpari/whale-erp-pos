## 권장 순서

1. **T00 → T01 → T02**: 골격, 틀, 로그인. 다른 모든 화면의 바탕이다. (2026-11-16 결정: 이번 범위, pnpm, Linux에서 개발 · Windows에서 빌드)
2. **T03**: 주문 수신. 모의 서버로 먼저 만든다. 주문 누락 0건이 최우선이다.
3. **T04 → T05**: 주문접수 화면과 팝업. 점원이 가장 오래 쓰는 화면이다.
4. **T11 → T12**: 프린터 설정과 출력. 실물 확인이 필요해 일찍 시작한다.
5. **T06 → T10**: 위젯과 알림음.
6. **T07**: 주문내역.
7. **T08, T09, T13**: 서로 의존하지 않으므로 함께 진행할 수 있다. 주문 흐름과 무관해 마지막에 둔다.

## 화면정의서로 달라진 것 (기존 문서와의 차이)

화면정의서가 기존 문서의 가정과 다른 부분이다. `AGENTS.md`(범위, 미결정 사항, 문서 위치)와 `docs/requests/backend-api-request.md`(7장)에는 2026-11-16에 반영했다. 나머지 문서(대표님 질문지, 협의 문서, 발표 자료)는 고치지 않았다.

| 항목 | 기존 문서 | 화면정의서 v0.8 | 고칠 문서 |
|---|---|---|---|
| 기기 인증 | 매장 코드로 기기 등록 | 점포번호 + 대표 휴대폰 번호 로그인, 마스터 계정 로그인, 자동 로그인 | `AGENTS.md` 범위, `docs/requests/backend-api-request.md` |
| 범위 | 주문 수신·접수·출력만 | 매장정보 편집, 메뉴품절, AI챗봇 인기메뉴 설정, 주문받기 ON/OFF, 픽업 상태, 주문내역(결제정보) 추가 | `AGENTS.md` 범위 |
| 출력물 | 주문서 | 주문서 + **영수증**(사업자 정보, 카드 승인 정보) | `AGENTS.md`, 백엔드 요청 문서 |

## 백엔드에 새로 요청할 것 (가정, 협의 전)

화면정의서대로 만들려면 기존 요청 문서에 없는 API가 필요하다.

1. 로그인 2종(점포번호, 마스터), 점포번호 찾기, 자동 로그인용 토큰
2. 주문받기 ON/OFF, 픽업 상태 변경. 프로그램이 꺼지거나 끊겼을 때 점포를 주문 불가로 바꾸는 방법
3. 주문 목록 조회(기간·상태·검색·페이지), 상태별 건수, 기간 합계
4. 주문 상세의 결제정보와 영수증용 사업자·카드 승인 정보
5. 상태 변경: 접수, 거부, 제조완료, 픽업완료, 접수 뒤 취소, 픽업완료 취소
6. 매장정보 조회·저장
7. 상품·옵션·카테고리 목록, 품절 목록 조회·추가·변경·삭제
8. AI챗봇 인기메뉴 조회·저장
