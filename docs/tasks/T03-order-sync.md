# T03. 주문 수신 · 상태 동기화 (화면 아님)

- **출처**: 화면정의서 v0.8 p.24(통합주문/접수판), `AGENTS.md` 핵심 설계 원칙 1~3, `docs/proposals/realtime-delivery-options.md`
- **선행 태스크**: T02 (로그인 토큰)
- **크기(추정)**: 대
- **관련 문의**: Q16, Q17, Q19, Q20

## 목표

서버에서 주문을 빠짐없이 받아 프로그램 안에 보관하고, 점원이 바꾼 상태를 서버에 보낸다. 화면(T04~T07)은 이 태스크가 만든 주문 목록을 보여 주기만 한다.

## 기획서의 주문 흐름 (p.24)

| 단계 | 고객 (픽업오더 앱) | 매장 프로그램 |
|---|---|---|
| 01 주문완료 | 주문·결제 완료 | 주문 카드 수신 + 알림음. 접수 대기에 카드 생성. 접수하지 않으면 반복 알림 |
| 02 주문접수 | 알림 "주문이 접수되었습니다." | [주문접수] 클릭 → 주문서 자동 출력 → 제조 중으로 이동 → 알림 자동 발송 |
| 03 조리완료 | 알림 "조리가 완료되었습니다" / "지금 받으러 와주세요" | [제조완료] 클릭 → 제조완료로 이동 → 알림 자동 발송 |
| 04 픽업완료 | 앱 주문 상태 완료. 주문 내역에 완료 표시 | [픽업완료] 클릭 → 주문 종료. 통계 반영 |

- 고객 알림은 매장 프로그램이 상태를 바꾸면 **서버가** 보낸다.
- 주문받기 OFF 상태에서는 01단계가 일어나지 않는다.
- 거부하면 고객 앱에 "매장사정으로 주문이 취소되었습니다."가 간다 (p.7).

## 상태 (기획서 기준)

| 상태 | 다음으로 갈 수 있는 상태 | 누가 바꾸나 |
|---|---|---|
| 접수대기 | 제조중(접수), 주문거부 | 점원 |
| 제조중 | 제조완료, 주문취소 | 점원 |
| 제조완료 | 픽업완료 | 점원 |
| 픽업완료 | 제조완료(완료 취소, Q22) | 점원 |
| 주문거부 / 주문취소 | 없음 | 점원 또는 고객 |

- "제조시작"이 접수와 다른 단계인지 확정되지 않았다 (Q16).
- 거부와 주문취소가 같은 상태인지 확정되지 않았다 (Q17).

## 만들 것

1. **수신 모듈**: 전달 방식(짧은 폴링 / SSE 등)은 미결정이다. 방식을 바꿔 끼울 수 있게 화면과 분리한다.
2. **빠짐 방지**: 주문마다 수신 확인(ack)을 보내고, 재연결·재시작 때 못 받은 주문을 다시 조회한다.
3. **중복 방지**: 같은 주문·이벤트가 두 번 와도 알림과 출력은 한 번만 한다.
4. **상태 변경 요청**: 접수·거부·제조완료·픽업완료·취소·완료 취소. 요청마다 멱등키를 붙인다. 서버가 성공을 돌려준 뒤에만 화면 상태를 바꾸고 주문서를 출력한다.
5. **연결 상태**: 끊김을 알아채고 화면에 알릴 수 있게 상태 값을 제공한다 (화면 정의는 Q51).
6. **반복 알림 신호**: 접수대기 주문이 남아 있다는 신호를 알림 모듈(T06)에 준다 (Q20).
7. **모든 서버 요청에 시간 제한** (2026-11-16 사용자 결정, T01에서 넘김): 서버가 응답하지 않아도 화면이 "처리 중"으로 멈추지 않게 한다. 특히 로그아웃 · 시스템종료 전 "주문 중단" 요청이 멈추면 점원이 프로그램을 끌 수 없다. 몇 초로 할지는 T03 스펙에서 정한다.
8. **점포 주문받기 상태 맞추기** (2026-11-16 사용자 결정): 로그인 직후 서버의 주문받기 상태를 조회해 화면과 맞춘다. 조회 API는 백엔드에 요청했다 (`docs/requests/backend-api-request.md` 7.3절 18번).

## 가정 (확정 전)

- 전달 방식과 API 형태는 `AGENTS.md` "미결정 사항"이다. 모의 서버로 먼저 만들고, 확정되면 수신 모듈만 바꾼다.
- 접수 뒤 매장 취소(제조중 취소)는 기획서에 새로 나온 동작이다. 환불은 서버 담당이며, `docs/requests/backend-api-request.md` 3.5절의 취소 정책 제안과 맞춰야 한다.

## 완료 기준

- 모의 서버에서 주문 100건을 연속으로 보내도 빠짐·중복이 0건이다.
- 프로그램을 껐다 켜도, 연결을 끊었다 이어도 못 받은 주문이 다시 들어온다.
- 같은 상태 변경을 두 번 보내도 한 번만 적용된다.
- 서버가 실패를 돌려주면 화면 상태가 바뀌지 않고 출력도 하지 않는다.
