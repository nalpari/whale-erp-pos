- **이번 범위 밖**: 알림음 종류 추가(Q44: 새 주문 · 경고 두 가지뿐), 소리 파일 교체.

## 3. 화면 (p.18)

| 번호 | 요소 | 내용 |

| 2 | 표시할 주문 상태 | ☑접수대기(늘 체크, 막힘 · 「항상 표시」) · ☑제조중 · ☑제조완료. 픽업완료 칸은 없다 (Q31: 픽업완료되면 카드가 사라짐) |

| 5 | 미리보기 | 오른쪽에 화면 모양 상자를 그리고 고른 모서리에 예시 위젯 카드를 보인다. `<` `>`로 접수대기 · 제조중 · 제조완료 예시를 넘긴다. 예시 데이터는 고정 문구(실제 주문 아님) |

- 버튼 · 체크 · 슬라이더 손잡이는 터치로 다룰 수 있게 44px 이상.
- 1024 × 768에서 스크롤 없이 들어가게 한다(들어가지 않으면 세로 스크롤).

## 4. 알림음 크기 (T06 11장 K · Q44)

- T06의 지금 소리를 크기 **40**으로 본다. 크기는 고르게 커진다: 20 = 지금의 절반, 40 = 지금, 100 = 지금의 2배 (11장 D).
- 최소 20 (0으로 못 내림, 새 주문을 못 듣는 일 방지).
- 크기는 새 주문 · 경고 두 소리에 같이 적용된다.
- 크게 해도 소리가 찢어지지(깨지지) 않게 한다. 방법(브라우저 기본 압축 기능 등)은 작업 세션이 정해 보고한다. 새 라이브러리 없이.
- 미리듣기는 지금 슬라이더 값으로 한 번 울린다.

## 5. 저장 · 반영

- 저장 방식 · 저장 위치는 11장 A · B.
- 저장하면 바로 반영한다: 위젯이 떠 있으면 고른 모서리로 옮기고, 끈 상태의 카드는 사라지고, 다음 알림음부터 새 크기.
- 다시 켜도 유지한다 (PC마다, Q15).
- 저장된 값이 깨졌거나 없으면 기본값(접수대기 · 제조중 · 제조완료, 우하단, 40)으로 시작하고 로그를 남긴다.

## 7. 로그

- 남길 것: 설정 읽기 · 저장 실패(원인 요약만).
- 남기지 않을 것: 개인정보는 없는 화면이라 해당 없음.

## 8. 테스트 전략

- 설정 읽기 · 쓰기: 기본값, 깨진 값 → 기본값, 범위 밖 크기 → 20~100으로 맞춤, 접수대기는 늘 포함.
- 화면: 접수대기 체크가 막힘, 제조중 · 제조완료 체크, 위치 선택 → 미리보기 이동, 슬라이더 값 · 숫자, 미리듣기가 지금 값으로 재생기를 부름, 저장 → 위젯 · 재생기에 반영, 다시 열면 유지.
- 크기 계산: 40 = 지금 소리, 100 = 2배, 20 = 절반.

## 9. 경계

- **항상**: PC에만 저장. 접수대기는 늘 위젯에 보인다.
- **먼저 묻기**: 새 라이브러리, 스펙에 없는 설정 항목.
- **하지 않기**: 서버 저장, 알림음 종류 추가.

## 10. 완료 기준

1. 두 계정 모두 바꿀 수 있고, 접수대기 체크는 풀 수 없다 (테스트).
2. 저장한 설정이 다시 켠 뒤에도 유지되고 위젯 · 알림음에 바로 반영된다 (테스트 + 실제 창).
3. 미리듣기가 지금 크기로 소리를 내고, 100에서도 소리가 깨지지 않는다 (테스트 + 사용자 귀).
4. 미리보기가 위치 · 상태 선택을 바로 보여 준다 (테스트).
5. 위젯이 고른 모서리로 옮겨 뜬다 (Linux X11 실제 창 + Windows).
6. ① lint · typecheck · format · test · build · Rust 검사 통과, ② · ③ 리뷰 완료.
