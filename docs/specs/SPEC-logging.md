# 스펙: 공통 로그 · 오류 기록 (`logging`)

- **태스크**: T14 (Plane WHALEERPPO-15), 태스크 문서 `docs/tasks/T14-logging.md`
- **근거**: 화면정의서에 없음. T11 ③ 리뷰 보류 사항(릴리스 Windows 빌드에서 오류 로그가 남지 않음). **"로그 확인" 화면은 개발자가 추가한 기능**이다 (사용자 결정 2026-11-17)
- **선행**: T00, T01(더보기 메뉴)
- **상태**: 승인 (2026-11-17, 사용자)

## 1. 목표

매장 PC에서 문제가 생겼을 때 원인을 찾을 수 있게, 화면(React)과 Rust의 오류 · 경고 · 주요 사건을 PC 파일에 남긴다. 점원도 앱 안에서 최근 로그를 보거나 로그 폴더를 열어 파일을 보낼 수 있게 한다.

- **이번 범위 밖**: 로그를 서버로 보내기, 오류 자동 신고, 로그 검색 · 필터 화면.

## 2. 로그 남기기

### 2.1 방법

- Tauri 공식 로그 플러그인을 쓴다 (사용자 결정 2026-11-17, A-1). 공식 문서 기준 (https://v2.tauri.app/plugin/logging/, 2026-11-17 확인):
  - Rust: `tauri-plugin-log` (docs.rs 기준 2.10.2), Rust 쪽에서 로그를 남길 때 쓰는 `log` crate (0.4)
  - 화면: `@tauri-apps/plugin-log`
  - 권한: `log:default`
  - 정확한 버전과 설치 방법은 작업 세션이 공식 문서로 다시 확인하고 추가 전에 보고한다.
- 로그 파일은 플러그인 기본 위치(`LogDir`)에 둔다. 공식 문서상 Windows는 `{LocalAppData}\{식별자}\logs`, 지금 식별자로는 `C:\Users\<사용자>\AppData\Local\com.whale.pickuporder.dev\logs`다. Linux는 `~/.local/share/{식별자}/logs`.

### 2.2 설정

| 항목 | 값 | 근거 |
|---|---|---|
| 남길 수준 | 정보(info) 이상: 오류 · 경고 · 주요 사건 | 사용자 결정 B-1 |
| 파일 크기 | 파일 하나 최대 5MB | 사용자 결정 C-1 |
| 보관 | 최근 파일 5개 정도만 남긴다 (최대 약 25MB). 플러그인의 `RotationStrategy::KeepSome`으로 한다. 정확히 몇 개가 남는지(현재 파일 포함 여부)는 작업 세션이 확인해 보고한다 | 사용자 결정 C-1 |
| 시간 | 한국 시간(PC 로컬 시간). 플러그인 기본은 UTC라 `TimezoneStrategy::UseLocal`로 바꾼다 | 사용자 결정 D-1 |
| 형식 | 플러그인 기본 `날짜[대상][수준] 내용` | |

### 2.3 남기는 것

- **화면의 `console.warn` · `console.error`**: 공식 문서의 방식대로 로그 파일로도 보낸다. 지금 코드의 `console.error`(T01 · T02 · T11)가 그대로 파일에 남는다.
- **Rust의 오류**: 지금 `eprintln`으로 남기는 곳을 `log` 매크로로 바꾼다.
- **주요 사건 (info)**: 다음만 남긴다. 화면에서 부르는 작은 로그 함수(`src/shared/log/` 예상)를 둔다.
  1. 앱 시작 (버전) · 종료
  2. 로그인 성공 (계정 종류만: 점포번호 / 마스터), 로그인 실패 (종류만: 아이디 · 비밀번호 틀림 / 네트워크 등), 로그아웃
  3. 자동 로그인 재개 결과 (성공 / 만료로 토큰 삭제 / 네트워크 오류로 토큰 유지)
  4. 주문받기 ON/OFF 요청 결과
  5. 시험 인쇄 결과 (프린터 이름, 성공 / 실패)
  6. 설정 저장 · 읽기 실패

### 2.4 남기지 않는 것 (항상)

- 고객 이름 · 연락처 · 카드 정보, 로그인 비밀번호(대표 휴대폰 번호), 마스터 비밀번호, 토큰. 주문은 `orderId`로만 남긴다 (`AGENTS.md` "개인정보 · 로그").
- 오류 객체를 통째로 남기지 않고 `src/shared/error-summary.ts`로 요약한다.
- 점포 고유번호 · 마스터 아이디도 남기지 않는다 (계정 종류만 남긴다). 누가 로그인했는지는 점포명으로 충분하다.

## 3. "로그 확인" 화면 (개발자 추가)

### 3.1 들어가기

- 더보기(⋮) 메뉴에 **[로그 확인]**을 추가한다 (사용자 결정 2026-11-17, H-2).
- **점포번호 계정 · 마스터 계정 모두** 쓸 수 있다 (사용자 결정 G-2: 직원에게 마스터 계정을 주지 않아도 오류를 찾을 수 있게).
- **로그인 전에도** 보인다. 로그인 · 자동 로그인 문제를 볼 수 있게 한다 (임시 결정, 스펙 승인 때 확인).
- 누르면 탭 영역 대신 "로그 확인" 화면으로 바뀐다. [닫기]를 누르면 들어오기 전 화면(탭)으로 돌아간다.

### 3.2 화면 (사용자 결정 F-3: 폴더 열기 + 최근 로그 보기)

1. 제목 "로그 확인"
2. "로그 위치: {로그 폴더 경로}"
3. 버튼 [로그 폴더 열기]: Windows 탐색기로 로그 폴더를 연다. 파일을 그대로 보낼 때 쓴다.
4. 버튼 [새로고침]: 최근 로그를 다시 읽는다.
5. 최근 로그: 지금 쓰고 있는 로그 파일의 **마지막 200줄**. 고정폭 글꼴, 가장 최근 줄이 맨 아래, 화면을 열면 맨 아래로 스크롤한다. 줄이 길면 줄바꿈한다.
6. 버튼 [닫기]
7. 터치 우선: 버튼은 다른 화면과 같은 크기로 크게 만든다.

- 화면에 보이는 로그도 2.4절 때문에 개인정보가 없다.
- 로그 파일이 아직 없으면 "아직 기록된 로그가 없습니다."
- 읽기 실패면 "로그를 불러올 수 없습니다."
- 폴더 열기 실패면 "로그 폴더를 열 수 없습니다."
- 위 문구는 모두 임시다 (화면정의서에 없는 화면).

### 3.3 Rust 쪽

- `read_recent_logs(lines: u32) -> { path, lines }`: 로그 폴더 경로와 현재 파일의 마지막 N줄. 파일 전체를 메모리에 올리지 않는다 (최대 5MB이므로 끝에서부터 읽는다).
- `open_log_dir()`: Windows는 탐색기(`explorer.exe`), Linux는 `xdg-open`, macOS는 `open`으로 연다. **새 라이브러리 없이** 운영체제 명령을 부른다. 경로는 앱이 정한 로그 폴더만 연다 (화면에서 경로를 받지 않는다).

## 4. 구조

```
src/
  shared/
    log/                 주요 사건 로그 함수, console.warn · error 연결
  features/
    log-viewer/          "로그 확인" 화면
    app-shell/           더보기 메뉴에 [로그 확인] 추가, 화면 전환
src-tauri/src/
  lib.rs                 로그 플러그인 등록 (크기 · 보관 · 시간대)
  log_viewer.rs          read_recent_logs, open_log_dir
```

경로는 예상이다. 작업 세션이 기존 구조에 맞춰 정하고 보고한다. 명령어와 코드 스타일은 `SPEC-app-shell.md` 4장, 6장과 같다.

## 6. 경계

- **항상**: 2.4절의 개인정보를 남기지 않는다. 로그 폴더 밖의 경로를 열거나 읽지 않는다.
- **먼저 묻기**: 2.1절 외의 라이브러리 · 플러그인 추가(폴더 열기용 opener 플러그인 포함). 주요 사건 목록(2.3) 밖의 것을 info로 남기기.
- **하지 않기**: 로그를 서버로 보내기, 로그 지우기 버튼, 로그 검색.

## 7. 완료 기준

1. 릴리스 빌드에서도 화면 · Rust의 오류와 주요 사건이 로그 파일에 남는다 (Linux 확인 + Windows 체크리스트).
2. 로그 파일이 5MB를 넘으면 새 파일로 넘어가고 오래된 파일은 정해진 개수만 남는다.
3. 로그 시간이 한국 시간이다.
4. 로그에 2.4절의 개인정보가 남지 않는다 (단위 테스트 + 코드 확인).
5. 더보기 메뉴의 [로그 확인]이 로그인 전 · 두 계정 모두에서 보이고, 로그 화면에서 경로 · 최근 200줄 · 폴더 열기 · 새로고침 · 닫기가 된다 (화면 테스트 + Linux 창 확인).
6. ① lint · typecheck · test · build · Rust 검사 통과, ② · ③ 리뷰 완료 (리뷰는 Opus 5.5 하위 에이전트).
