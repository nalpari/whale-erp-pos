# 스펙: 환경설정 — 프린터설정 (`settings-printer`)

- **태스크**: T11 (Plane WHALEERPPO-12), 태스크 문서 `docs/tasks/T11-settings-printer.md`
- **근거**: 화면정의서 v0.8 p.19 (`docs/references/pickup-order-screen-spec-v0.8-260717.pdf`), 기획자 답변 Q10 · Q15 · Q45 · Q46 (`docs/tasks/planner-answers.md`). **둘이 다르면 기획자 답변을 따른다.**
- **선행**: T01 프로그램 틀, T02 로그인
- **상태**: 승인 (2026-11-18, 사용자, 개정판). 처음 판은 2026-11-17 승인. 바뀐 점은 11장

## 1. 목표

주문서 · 영수증을 낼 프린터를 최대 3대 등록하고, 등록한 프린터로 **시험 인쇄**를 해서 연결을 확인한다. 커넥터가 아직 없으므로 Windows 기본 가상 프린터("Microsoft Print to PDF")로 등록부터 시험 인쇄까지 확인할 수 있어야 한다.

- **이번 범위 밖**: 실제 주문서 · 영수증 출력과 양식, 여러 프린터에 나눠 내는 규칙(주문서는 체크한 프린터 모두, 영수증은 체크한 프린터 중 슬롯 번호가 가장 앞선 한 대, Q45 ①), 출력 실패 알림(Q47) — 모두 T12. 포트 직접 출력(ESC/POS). 서버 저장(Q15: 프린터 설정은 PC마다 저장).

## 2. 화면 요구사항 (p.19)

환경설정 탭 > [프린터설정] 하위 탭 (T01이 만든 자리)에 그린다.

### 2.1 프린터 칸 (슬롯 3개)

1. 칸은 항상 3개, 제목은 "슬롯 {번호} — {프린터 이름}". 비어 있으면 "슬롯 {번호} — 프린터 없음".
2. 등록된 칸에는 다음을 보인다.
   - 용도 이름 (회색 칸, 예: "카운터 영수증") + 연필 버튼. 연필을 누르면 그 자리에서 고치고, Enter나 칸 밖을 누르면 저장, Esc면 취소한다.
   - "출력 항목" [ ] 주문서 [ ] 영수증 (고객 요청 시) 체크 상자.
   - "용지 폭" (o) 58mm (o) 80mm 라디오. 새 칸 기본값 80mm (Q45 ⑤). 이 값은 저장만 하고 T12 출력 양식이 쓴다 (12장 C).
   - [시험 인쇄] 버튼 (Q45 ④, 2.3절).
   - [연결 해제] 버튼 (빨간 테두리). 누르면 확인 없이 바로 빈 칸이 된다.
3. 빈 칸에는 [+ 프린터 추가] 버튼(파란 테두리)만 있다.
4. 화면 아래에 안내 "프린터 추가 방법"과 세 줄을 화면정의서 원문 그대로 보인다.
   - ① 프린터를 USB 또는 네트워크로 PC에 연결합니다
   - ② Windows 프린터 드라이버를 설치합니다
   - ③ '+ 프린터 추가' 버튼 클릭 → 목록에서 해당 프린터를 선택합니다

### 2.2 프린터 추가 (목록에서 고르기)

1. [+ 프린터 추가]를 누르면 **이 PC의 Windows에 설치된 프린터 목록** 팝업을 띄운다. 제목 "프린터 선택", 프린터 이름 목록, [취소]. 이름을 누르면 그 칸에 등록하고 팝업을 닫는다.
2. 다른 칸에 이미 등록된 프린터는 목록에서 빼거나 누를 수 없게 한다. 같은 프린터가 두 칸에 들어가 주문서가 두 번 나오는 일을 막는다.
3. 목록이 비었으면 "설치된 프린터가 없습니다." 를 보인다.
4. 목록을 못 읽으면(오류) "프린터 목록을 불러올 수 없습니다." 를 보인다.
5. 새로 등록한 칸의 기본값: 용도 이름은 빈 값(회색 칸에 안내 글 "용도 입력"), 주문서 체크, 영수증 해제, 용지 폭 80mm.

### 2.3 시험 인쇄 (Q45 ④)

1. 등록된 칸의 [시험 인쇄]를 누르면 그 프린터로 시험 페이지를 보낸다. 보내는 동안 버튼을 다시 누를 수 없다.
2. 시험 페이지 내용 (Windows 일반 인쇄로 글자를 그린다. 글꼴은 "맑은 고딕"):
   - "픽업오더 주문접수 시험 인쇄"
   - "프린터: {프린터 이름}" / "용도: {용도 이름}" (빈 값이면 줄을 뺀다)
   - "점포: {점포명}"
   - "출력 시각: {YYYY-MM-DD HH:mm:ss}"
   - 한글 확인 문장 "가나다라마바사 아메리카노 1잔"과 숫자 "0123456789"
3. 결과는 버튼 옆에 글로 보인다.
   - 성공: "시험 인쇄를 보냈습니다." (Windows 인쇄 대기열에 넣었다는 뜻이다. 종이가 실제로 나왔는지는 알 수 없다. Q47)
   - 실패: "시험 인쇄에 실패했습니다. 프린터 연결과 드라이버를 확인해 주세요."
4. 영수증 프린터에서 용지를 자르는 것은 드라이버 설정에 맡긴다.

### 2.4 권한

- **점포번호 계정과 웨일ERP 계정 모두 보기 · 바꾸기 · 시험 인쇄가 된다** (기획자 Q10). 프린터를 갈 때마다 관리자가 와야 하는 일을 막는다.
- 2026-11-17에 넣은 점포번호 계정 안내 줄("프린터 설정은 마스터 계정만 변경할 수 있습니다. …")과 입력 막기를 지운다 (12장 A).

### 2.5 저장

- 바꾸면 바로 저장한다 (Q45 ③). 저장에 성공하면 토스트 "저장되었습니다" 를 보인다 (Q45 ③, 메뉴품절 Q42와 같은 방식). 모양은 12장 B.
- 「주문서」가 체크된 칸이 하나도 없으면 칸 3개 위에 안내 "주문서를 출력할 프린터가 없습니다. 주문을 접수해도 주문서가 출력되지 않습니다." 를 계속 보인다 (Q45). 프린터가 하나도 없을 때도 보인다. 설정을 불러오지 못한 상태(아래)에서는 보이지 않는다.
- **이 PC에 저장한다** (Q15: 프린터 설정은 PC마다). 프로그램을 다시 켜도 유지된다. 로그아웃해도 지우지 않는다 (프린터는 PC에 붙어 있으므로).
- 저장에 실패하면 화면 값을 저장 전으로 되돌리고 "설정을 저장하지 못했습니다." 를 보인다.
- 설정 파일이 있는데 읽지 못하면(파일 없음 · 모양 틀림이 아닌 읽기 오류. 예: 백신이 파일을 잡고 있음) "설정을 불러오지 못했습니다." 를 보이고, 칸 3개는 비운 채 모든 고치기와 시험 인쇄를 막는다. 프린터설정 탭을 다시 열면 다시 읽는다 (사용자 결정 2026-11-17). 멀쩡한 설정을 빈 값으로 덮어쓰지 않게 한다.
- 저장된 프린터가 지금 Windows 목록에 없어도 칸에서 지우지 않는다. 이름 옆에 "(찾을 수 없음)"을 붙인다. 시험 인쇄는 실패 문구가 나온다.

## 3. 데이터 · 외부 연동

### 3.1 설정 모양

```ts
// src/shared/printer/printer-settings.ts (예상 경로)
export interface PrinterSlot {
  printerName: string; // Windows 프린터 이름 (식별자로도 쓴다)
  purpose: string;     // 용도 이름, 빈 값 가능
  printOrder: boolean;   // 주문서: 주문접수 때 자동 출력 (T12가 쓴다)
  printReceipt: boolean; // 영수증 (고객 요청 시) (T12가 쓴다)
  paperWidth: 58 | 80;   // 용지 폭 mm (T12가 쓴다, Q45 ⑤)
}
export interface PrinterSettings {
  version: 1;
  slots: [PrinterSlot | null, PrinterSlot | null, PrinterSlot | null];
}
```

- 처음에는 세 칸 모두 `null`.
- **2026-11-17 판으로 저장한 파일(칸에 `paperWidth`가 없음)은 깨진 파일로 보지 않고 `paperWidth: 80`으로 채워 읽는다.** 이미 등록한 프린터 설정이 지워지지 않게 한다. `version`은 1 그대로 둔다. 58 · 80이 아닌 값은 모양이 다른 파일로 본다.
- 저장 파일이 없거나 모양이 다르면 빈 설정으로 시작한다. 모양이 다른 파일은 `printer-settings.json.broken`으로 사본을 남긴다(로그에 이유만 남긴다). 사본이 이미 있으면 덮어쓰지 않아 처음 깨진 내용을 남긴다 (2026-11-18 사용자 결정). 용지 폭 값 하나만 틀려도 파일 전체를 모양이 다른 파일로 본다 (2026-11-18 사용자 결정, 그대로 유지).
- 그 밖의 읽기 오류는 빈 설정으로 시작하지 않고 오류로 알린다 (2.5절).

### 3.2 화면이 부르는 인터페이스

화면 코드는 Tauri를 직접 부르지 않는다 (T01 `window.ts`와 같은 방식).

```ts
export interface PrinterApi {
  listPrinters(): Promise<string[]>;            // Windows에 설치된 프린터 이름
  printTestPage(printerName: string, lines: string[]): Promise<void>;
}
export interface PrinterSettingsStore {
  load(): Promise<PrinterSettings>;
  save(settings: PrinterSettings): Promise<void>;
}
```

- Tauri 구현: Rust 명령 `list_printers`, `print_test_page`, `load_printer_settings`, `save_printer_settings`.
- 테스트 · 브라우저 개발 모드: 가짜 구현(정해 둔 프린터 이름 몇 개, 메모리 저장). "모의 데이터"라고 주석을 단다.

### 3.3 Rust 쪽

- **프린터 목록 · 시험 인쇄 (Windows)**: Win32 API(인쇄 스풀러의 프린터 목록, GDI 인쇄)를 Microsoft 공식 Rust 라이브러리 `windows` 또는 `windows-sys`로 부른다 (추가 승인 2026-11-17). 둘 중 무엇을 쓸지는 작업 세션이 이유와 함께 먼저 보고하고 승인받는다. `Cargo.toml`에서 Windows 대상에만 넣는다.
- **Windows가 아닐 때 (Linux · Mac 개발)**: 목록은 빈 배열, 시험 인쇄는 "지원하지 않는 OS" 오류를 돌려준다.
- **설정 파일**: Tauri 앱 설정 폴더(`app_config_dir`)의 `printer-settings.json`. 이미 있는 `serde_json`으로 읽고 쓴다. 새 라이브러리나 Tauri 플러그인을 쓰지 않는다.
- 필요한 Tauri 권한만 연다.

## 6. 경계

- **항상**: 화면정의서 · 기획자 답변 문구는 원문 그대로. 화면 코드는 인터페이스만 부른다. 로그에 고객 정보를 남기지 않는다.
- **먼저 묻기**: `windows`/`windows-sys` 외의 라이브러리나 Tauri 플러그인 추가. 화면정의서와 다른 동작 추가.
- **하지 않기**: 포트 직접 출력(ESC/POS), 프린터 상태 감지, 주문서 · 영수증 양식, 여러 프린터 출력 규칙, 서버 저장.

## 7. 완료 기준

1. 프린터설정 탭에 칸 3개가 나오고, 프린터 목록에서 등록 · 해제, 용도 이름 수정, 출력 항목 체크, 용지 폭 선택을 할 수 있다 (화면 테스트).
2. 바꾼 설정이 바로 저장되고 "저장되었습니다" 토스트가 뜨며, 프로그램을 다시 켜도 유지된다. 2026-11-17 판으로 저장한 설정도 지워지지 않고 용지 폭 80mm로 읽힌다 (단위 · Rust 테스트 + Windows 수동 확인).
3. 같은 프린터를 두 칸에 등록할 수 없다 (테스트).
4. [시험 인쇄]가 그 프린터로 시험 페이지를 보내고 성공 · 실패 문구를 보인다 (화면 테스트 + Windows에서 "Microsoft Print to PDF"로 수동 확인).
5. 점포번호 계정도 웨일ERP 계정과 똑같이 모두 할 수 있고, "마스터 계정만" 안내 줄이 없다 (화면 테스트).
5-1. 「주문서」 체크된 칸이 없으면 안내가 보이고, 하나라도 있으면 사라진다 (화면 테스트).
6. 출력 항목 · 용지 폭 값이 T12에서 읽을 수 있는 모양(3.1절)으로 저장된다 (단위 테스트).
7. ① lint · typecheck · format · test · build · Rust 검사 통과, ② · ③ 리뷰 완료.

| 저장 | 저장 버튼 없음 | 바꾸면 바로 저장 + "저장되었습니다" 토스트 | 기획자 Q45 ③ |
