# 스펙: 로그인 · 점포번호 찾기 (`login`)

- **태스크**: T02 (Plane WHALEERPPO-3), 태스크 문서 `docs/tasks/T02-login.md`
- **근거**: 화면정의서 v0.8 p.8~10 (`docs/references/pickup-order-screen-spec-v0.8-260717.pdf`)
- **선행**: T01 프로그램 틀
- **상태**: 승인 (2026-11-16, 사용자)

## 1. 목표

점원과 점주가 두 가지 계정으로 로그인하고, 계정 종류에 따라 바꿀 수 있는 것이 달라진다. 점포번호 계정은 자동 로그인으로 매일 아침 로그인 화면을 건너뛸 수 있다.

- **이번 범위 밖**: 실제 백엔드 연동(API 미정, 모의 구현으로 만든다), 로그인 알림 발송(서버 담당), 마스터 계정의 점포 선택(Q09 답변 전), 로그인 실패 잠금(Q13).

## 2. 계정과 권한

| | 점포번호 계정 (`store`) | 마스터 계정 (`master`) |
|---|---|---|
| 아이디 | 점포 고유번호 | 파트너오피스 ERP 아이디 |
| 비밀번호 | 대표 휴대폰 번호 | ERP 비밀번호 |
| 탭 | 주문접수 · 주문내역 · 매장정보 · 메뉴품절 · 환경설정 | 같음 |
| 환경설정 | **조회만** | 변경 가능 |
| 자동 로그인 | 있음 | 없음 |

- 권한은 로그인 응답의 계정 종류로 정한다. 화면은 `canEditSettings` 하나만 보고 환경설정 입력을 막는다. 실제 막는 일은 각 설정 태스크(T10, T11, T13)가 이 값을 써서 한다.
- 서버에 저장하는 설정은 서버에서도 권한을 확인해야 한다 (백엔드 요청 문서 7.3절 15번).

## 3. 화면 요구사항

### 3.1 점포 번호로 로그인 (기본 탭, p.8)

1. 탭 [점포 번호로 로그인] [마스터 계정으로 로그인]. 처음에는 점포 번호 탭.
2. 점포 고유번호 칸 (안내 글 "점포 고유번호").
3. 대표 휴대폰 번호 칸 (안내 글 "대표 휴대폰 번호"). 입력값을 가리고, 눈 아이콘으로 보이기/가리기를 바꾼다.
4. [ ] 자동로그인 체크 상자. 처음에는 해제.
5. [점포번호 찾기] 글자 버튼 → 점포번호 찾기 팝업.
6. [로그인] 버튼. 두 칸이 모두 채워져야 누를 수 있다 (그림에서 회색 버튼, 사용자 결정 2026-11-16).
7. 실패하면 버튼 아래에 "! 아이디와 비밀번호가 올바르지 않습니다."를 빨간 글씨로 보인다. 입력을 고치면 문구를 지운다.

- 휴대폰 번호 칸은 **숫자만** 입력받는다. 숫자가 아닌 글자는 입력되지 않는다 (사용자 결정 2026-11-16). 붙여 넣은 값에 하이픈 등이 섞여 있으면 숫자만 남긴다.
- Enter 키로 로그인할 수 있다.

### 3.2 마스터 계정으로 로그인 (p.9)

1. 마스터 아이디 칸 (안내 글 "마스터 아이디 입력"), 마스터 비밀번호 칸 (안내 글 "마스터 비밀번호 입력", 가림 + 눈 아이콘), [로그인].
2. 자동로그인과 점포번호 찾기는 보이지 않는다.
3. 실패 문구는 3.1과 같다.
4. 탭을 바꾸면 입력값과 오류 문구를 지운다.

### 3.3 점포번호 찾기 팝업 (p.10)

1. 제목 "점포번호 찾기", 오른쪽 위 ×.
2. 안내 "파트너오피스에 등록된 대표 이메일로 점포번호를 찾을 수 있습니다."
3. 대표자 이름 칸("대표자 이름 입력"), 대표 이메일 칸("대표 이메일 입력").
4. [점포번호 찾기] [취소]. 두 칸이 모두 채워져야 찾기를 누를 수 있다.
5. 실패 문구 (두 줄): "파트너오피스에 일치하는 정보가 없습니다." / "대표자 이름과 이메일을 확인 후 다시 시도해 주세요."
6. 성공하면 같은 팝업이 완료 상태로 바뀐다.
   - 제목 "점포번호 찾기 완료"
   - "{점포명} 님의 점포번호 찾기가 완료되었습니다." (점포명은 파란 글씨)
   - 가려진 점포번호 (예: HC-1\*\*\*4-PO, 서버가 가린 값을 준다)
   - [로그인] [닫기]
7. 완료 상태의 [로그인]: 팝업을 닫고 점포 번호 탭으로 돌아간다. 점포 고유번호 칸은 **비워 둔다** (Q12 답변 전 임시 처리, 사용자 결정 2026-11-16).

### 3.4 로그인 성공 뒤

1. T01의 "로그인 후" 상태로 바뀌고 주문접수 탭을 보인다. 헤더에 점포명이 나온다.
2. 자동로그인을 체크했으면 다음 실행 때 로그인 화면을 건너뛴다 (4장).
3. 로그아웃(T01)하면 저장한 자동 로그인 정보를 지운다.

## 4. 자동 로그인

- 점포번호 계정에서 체크했을 때만 저장한다.
- **휴대폰 번호(비밀번호)를 PC에 저장하지 않는다.** 로그인 응답의 재발급용 토큰만 저장한다고 가정한다.
- 프로그램 시작 시 저장된 토큰이 있으면 서버에 확인해 로그인 상태로 시작한다. 실패하면 로그인 화면을 보인다. 이때 별도 안내 문구는 없다 (화면정의서에 없음).
  - 만료 · 폐기(`SessionExpiredError`)면 토큰을 지운다.
  - 네트워크 등 그 밖의 오류면 토큰을 남긴다. 다음 실행 때 다시 시도한다 (사용자 결정 2026-11-16). 아침에 인터넷이 잠깐 끊긴 매장이 자동 로그인을 잃지 않게 한다.
- 서버에 확인하는 동안에는 로그인 폼 대신 빈 화면을 보인다. 헤더는 "로그인 후 이용해주세요." 그대로다 (사용자 결정 2026-11-16). 로그인 폼이 잠깐 보였다 사라지는 깜빡임을 막는다.
- **저장 위치: Windows 보안 저장소(자격 증명 관리자 등)** (사용자 결정 2026-11-16). Rust 크레이트 `keyring` 4.2와 직접 만든 Rust 명령 3개(저장 · 읽기 · 삭제)로 저장한다 (사용자 결정 2026-11-16). 테스트와 브라우저 개발 모드에서는 메모리 저장 구현으로 바꾼다.

## 5. 데이터 · 외부 연동 (가정, 백엔드 협의 전)

```ts
// src/shared/api/auth.ts
export type AccountType = "store" | "master";

export interface Session {
  accountType: AccountType;
  store: { id: string; name: string };
  accessToken: string;
  /** 자동 로그인용. 점포번호 계정에서만 받는다고 가정한다. */
  refreshToken?: string;
}

export interface AuthApi {
  loginWithStoreCode(storeCode: string, phone: string): Promise<Session>;
  loginWithMaster(masterId: string, password: string): Promise<Session>;
  /** 저장된 재발급 토큰으로 다시 로그인한다 (자동 로그인). */
  resume(refreshToken: string): Promise<Session>;
  findStoreCode(ownerName: string, email: string): Promise<{ storeName: string; maskedStoreCode: string }>;
}
```

- 아이디 · 비밀번호가 틀리면 `InvalidCredentialsError`, 점포번호 찾기에서 정보가 없으면 `StoreNotFoundError`, 재발급 토큰이 만료 · 폐기됐으면 `SessionExpiredError`(`resume` 전용)를 던진다고 가정한다. 그 밖의 실패(네트워크 등)는 일반 오류로 처리한다.
- 모의 구현: 정해 둔 시험용 계정 하나씩(점포번호, 마스터)만 성공한다. 시험 값은 코드 상수로 두고 "모의 데이터"라고 주석을 단다. 실제 고객 · 점포 정보를 쓰지 않는다.
- 이 인터페이스는 백엔드 요청 문서 7.2절 1번과 맞춰 협의할 대상이다.

## 7. 테스트 전략

| 수준 | 대상 | 도구 |
|---|---|---|
| 단위 | 휴대폰 번호 숫자만 남기기, 권한 계산, 자동 로그인 시작 흐름(성공 · 만료 시 토큰 삭제 · 네트워크 오류 시 토큰 유지) | Vitest |
| 화면 | 탭 전환과 입력 초기화, 휴대폰 번호 칸에 숫자 외 입력 안 됨, 버튼 활성 조건, 실패 문구 표시 · 지우기, 눈 아이콘, 점포번호 찾기 성공 · 실패 · 완료 화면, 로그인 후 T01 전환 | React Testing Library |
| 수동 | 자동 로그인이 프로그램 재실행 뒤에도 동작하는지 | Windows 확인 체크리스트 |

- 화면 문구는 화면정의서 원문과 같은지 테스트로 확인한다.
- 로그와 테스트 출력에 휴대폰 번호 · 비밀번호를 남기지 않는다.

## 8. 경계

- **항상**: 비밀번호(휴대폰 번호)는 PC에 저장하지 않는다. 로그 · 오류 보고에 남기지 않는다. 문구는 화면정의서 원문 그대로.
- **먼저 묻기**: 토큰 저장용 라이브러리나 Tauri 플러그인 추가(4장). 화면정의서와 다른 동작. 마스터 계정에 점포가 여러 곳인 경우 처리.
- **하지 않기**: 실제 서버 주소 연결, 로그인 실패 잠금, 비밀번호 찾기 기능 만들기.

## 9. 완료 기준

1. 점포번호 계정과 마스터 계정이 모의 서버에서 로그인되고, 실패 문구가 기획서와 같다 (화면 테스트).
2. 점포번호 계정은 `canEditSettings`가 거짓, 마스터 계정은 참이다 (단위 테스트).
3. 마스터 탭에서는 자동로그인과 점포번호 찾기가 보이지 않는다 (화면 테스트).
4. 자동로그인을 체크하고 로그인하면 재실행 때 로그인 화면을 건너뛴다. 토큰이 만료되면 로그인 화면이 나오고 토큰이 지워진다. 네트워크 오류면 로그인 화면이 나오고 토큰은 남는다. 로그아웃하면 토큰이 지워진다 (단위 테스트 + Windows 수동 확인).
5. 점포번호 찾기의 실패 문구, 완료 화면, [로그인] · [닫기] · [취소] · × 동작이 기획서와 같다 (화면 테스트).
6. 휴대폰 번호가 PC 저장소와 로그에 남지 않는다 (테스트 또는 코드 확인).
7. ① lint · typecheck · test · build 통과, ② · ③ 리뷰 완료.
