# 스펙: 로그인 (`login`)

- **태스크**: T02 (Plane WHALEERPPO-3), 태스크 문서 `docs/tasks/T02-login.md`
- **근거**: 화면정의서 v0.8 p.8~10 (`docs/references/pickup-order-screen-spec-v0.8-260717.pdf`), 기획자 답변 Q06 · Q09~Q15 (`docs/tasks/planner-answers.md`). **둘이 다르면 기획자 답변을 따른다.**
- **선행**: T01 프로그램 틀
- **상태**: 승인 (2026-11-18, 사용자, 개정판). 처음 판은 2026-11-16 승인. 바뀐 점은 12장

## 1. 목표

매장 PC 한 대가 점포 하나를 맡는다. 점포 직원은 점포코드와 매장 프로그램 비밀번호로, 관리자는 웨일ERP 계정으로 로그인한다. 점포번호 계정은 자동 로그인으로 매일 아침 로그인 화면을 건너뛸 수 있다.

- **이번 범위 밖**: 실제 백엔드 연동(API 미정, 모의 구현으로 만든다), 새 PC 로그인 알림 발송(서버 · 웨일ERP 담당, Q11), 매장 프로그램 비밀번호 설정 화면(웨일ERP 담당, Q09), 환경설정 화면별 입력 막기(각 설정 태스크 T10 · T11 · T13이 3장의 권한 함수를 쓴다).

## 2. 계정과 권한

| | 점포번호 계정 (`store`) | 웨일ERP 계정 (`master`) |
|---|---|---|
| 입력 | 점포코드 + 매장 프로그램 비밀번호 | 웨일ERP 아이디 + 비밀번호 + 점포코드 |
| 누가 | 그 점포 직원 누구나 | 그 점포를 관리하는 웨일ERP 계정(BP 마스터 · BP 관리자 · 가맹마스터 · 가맹관리자) |
| 탭 | 주문접수 · 주문내역 · 매장정보 · 메뉴품절 · 환경설정 | 같음 |
| 자동 로그인 | 있음 | 없음 |

- 코드 식별자 `master`는 그대로 두고 화면 글자만 "웨일ERP 계정"으로 바꾼다. 이름만 바꾸는 수정이 여러 파일에 퍼지지 않게 하려는 것이다.
- 점포 선택 · 전환 화면은 없다. 다른 점포는 로그아웃 후 그 점포코드로 다시 로그인한다 (Q09).

### 환경설정 권한 (Q10)

| 환경설정 | 점포번호 계정 | 웨일ERP 계정 |
|---|---|---|
| 위젯 설정 | 보기 · 바꾸기 | 보기 · 바꾸기 |
| 프린터 설정 | 보기 · 바꾸기 | 보기 · 바꾸기 |
| AI챗봇 인기메뉴 설정 | 보기만 | 보기 · 바꾸기 |

- `canEditSettings(session)` 하나를 `canEditSetting(session, "widget" | "printer" | "aiPopular")`로 바꾼다. 지금 이 값을 쓰는 곳은 T11 프린터 화면뿐이다. 그 화면의 "마스터 계정만" 안내 줄을 빼는 일은 T11에서 한다. T02는 함수만 바꾸고, T11 화면은 새 함수에서 `"printer"` 값을 받도록 한 줄만 고친다 (그러면 점포 계정도 바로 바꿀 수 있게 된다).
- 서버에 저장하는 설정(AI챗봇 인기메뉴)은 서버에서도 권한을 확인해야 한다 (백엔드 요청 문서 7.3절 15번).

## 3. 화면 요구사항

### 3.1 점포번호로 로그인 (기본 탭)

1. 탭 [점포번호로 로그인] [웨일ERP 계정으로 로그인]. 처음에는 점포번호 탭.
2. 점포코드 칸 (안내 글 "점포코드 (예: ST000001)"). 자유 입력이고, 영문 소문자는 대문자로 바꿔 넣는다(st000001 → ST000001). 앞뒤 공백은 지운다. 형식 검사는 하지 않는다(틀리면 서버가 "올바르지 않습니다"로 답한다). 최대 20자.
3. 매장 프로그램 비밀번호 칸 (안내 글 "매장 프로그램 비밀번호"). 입력값을 가리고, 눈 아이콘으로 보이기 / 가리기를 바꾼다. 최대 20자.
4. [ ] 자동로그인 체크 상자. 처음에는 해제.
5. [로그인] 버튼. 두 칸이 모두 채워져야 누를 수 있다.
6. [로그인] 아래 안내 한 줄: "점포코드와 매장 프로그램 비밀번호는 웨일ERP 점포 상세에서 확인할 수 있습니다." (Q12). 누르는 기능은 없다.
7. Enter 키로 로그인할 수 있다.

### 3.2 웨일ERP 계정으로 로그인

1. 웨일ERP 아이디 칸("웨일ERP 아이디 입력"), 비밀번호 칸("웨일ERP 비밀번호 입력", 가림 + 눈 아이콘), 점포코드 칸(3.1과 같음), [로그인]. 세 칸이 모두 채워져야 누를 수 있다.
2. 자동로그인은 보이지 않는다.
3. [로그인] 아래 안내: "아이디 · 비밀번호를 잊으셨나요? 웨일ERP에서 찾을 수 있습니다. [웨일ERP 열기]" (Q14). [웨일ERP 열기]는 기본 브라우저로 웨일ERP 로그인 화면을 연다. 주소는 Rust 코드 상수 하나로 두고, 화면은 주소를 넘기지 않는다(아무 주소나 열지 못하게). 여는 방법은 T14 `open_log_dir`과 같다(explorer · xdg-open · open, 라이브러리 없음). 주소는 아직 임시값이다 (13장 C).
4. 탭을 바꾸면 비밀번호 · 아이디와 오류 문구를 지운다. 점포코드 칸은 지우지 않고 3.3의 기억한 값을 둔다.

### 3.3 마지막 점포코드 기억 (Q09 · Q15)

- 로그인에 **성공했을 때** 그 점포코드를 PC에 저장한다. 두 탭 모두 다음에 로그인 화면이 나오면 이 값을 점포코드 칸에 채워 둔다.
- 점포코드는 비밀값이 아니므로 보안 저장소가 아니라 화면 쪽 `localStorage`에 둔다 (2026-11-18 사용자 결정). 읽기 · 쓰기가 실패해도(저장소가 막힌 경우) 칸을 비워 두고 로그인은 그대로 된다.

### 3.4 오류 문구

버튼 아래 빨간 글씨 한 줄. 입력을 고치면 지운다.

| 경우 | 문구 | 탭 |
|---|---|---|
| 아이디 · 비밀번호(또는 점포코드 · 비밀번호)가 틀림 | ! 아이디와 비밀번호가 올바르지 않습니다. (화면정의서 원문) | 둘 다 |
| 픽업오더를 구독하지 않은 점포 | 픽업오더를 구독한 점포만 사용할 수 있습니다. | 둘 다 |
| 웨일ERP 계정이 관리하지 않는 점포 | 이 계정으로 관리할 수 없는 점포입니다. | 웨일ERP |
| 매장 프로그램 비밀번호 미설정 | 웨일ERP 점포 상세에서 매장 프로그램 비밀번호를 먼저 설정해 주세요. | 점포번호 |
| 연속 5번 틀려 잠김 | 로그인이 잠겼습니다. 5분 뒤에 다시 시도해 주세요. | 둘 다 |
| 네트워크 등 그 밖의 오류 | 서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요. (임시, 2026-11-16 결정 그대로) | 둘 다 |

- 잠금은 **서버가 판단한다**고 가정한다. 서버가 "잠김"으로 답하면 문구만 보인다. PC에서 틀린 횟수를 세거나 버튼을 막지 않는다. 잠금 범위가 "그 PC만"(Q13)이라 서버가 PC를 구분해야 하므로, 로그인 요청에 PC 이름을 보낸다 (5장).

### 3.5 로그인 성공 뒤

1. T01의 "로그인 후" 상태로 바뀌고 주문접수 탭을 보인다. 헤더에 점포명이 나온다.
2. 자동로그인을 체크했으면 다음 실행 때 로그인 화면을 건너뛴다 (4장).
3. 더보기의 [로그아웃]은 저장한 자동 로그인 정보를 지운다. [프로그램 종료] · 다시 켜기는 지우지 않는다 (Q06). 지금 동작과 같다.

## 4. 자동 로그인

- 점포번호 계정에서 체크했을 때만 저장한다.
- **매장 프로그램 비밀번호를 PC에 저장하지 않는다.** 로그인 응답의 재발급용 토큰만 저장한다고 가정한다.
- 프로그램 시작 시 저장된 토큰이 있으면 서버에 확인해 로그인 상태로 시작한다. 실패하면 로그인 화면을 보인다. 안내 문구는 없다.
  - 만료 · 폐기(`SessionExpiredError`)면 토큰을 지운다. 웨일ERP에서 매장 프로그램 비밀번호를 바꾸면 서버가 그 점포의 토큰을 폐기한다고 가정한다. 그러면 다음 실행 때 새 비밀번호로 다시 로그인하게 된다 (Q09).
  - 네트워크 등 그 밖의 오류면 토큰을 남긴다 (2026-11-16 결정 그대로).
- 서버에 확인하는 동안에는 로그인 폼 대신 빈 화면을 보인다 (2026-11-16 결정 그대로).
- 저장 위치: Windows 보안 저장소, `keyring` 크레이트 (2026-11-16 결정 그대로).

## 5. 데이터 · 외부 연동 (가정, 백엔드 협의 전)

```ts
// src/shared/api/auth.ts
export type AccountType = "store" | "master";

export interface Session {
  accountType: AccountType;
  store: { id: string; code: string; name: string };
  accessToken: string;
  /** 자동 로그인용. 점포번호 계정에서만 받는다고 가정한다. */
  refreshToken?: string;
}

export interface AuthApi {
  loginWithStoreCode(storeCode: string, password: string, deviceName: string): Promise<Session>;
  loginWithMaster(erpId: string, password: string, storeCode: string, deviceName: string): Promise<Session>;
  /** 저장된 재발급 토큰으로 다시 로그인한다 (자동 로그인). */
  resume(refreshToken: string): Promise<Session>;
}
```

- `findStoreCode`와 `StoreNotFoundError`는 지운다.
- 던지는 오류 (가정): `InvalidCredentialsError`, `NotSubscribedError`, `StoreNotManagedError`(웨일ERP 탭), `PasswordNotSetError`(점포번호 탭), `LoginLockedError`, `SessionExpiredError`(`resume` 전용). 그 밖은 일반 오류.
- `deviceName`: Windows 컴퓨터 이름. 라이브러리 없이 Rust에서 환경 변수 `COMPUTERNAME`(Windows), `HOSTNAME`(그 밖)으로 읽고, 없으면 빈 문자열을 보낸다 (2026-11-18 사용자 결정). 서버가 새 PC 알림(Q11)과 PC별 잠금(Q13)에 쓴다고 가정한다.
- 모의 구현: 시험용 계정 하나씩(점포번호, 웨일ERP)만 성공한다. 오류 경우마다 시험용 점포코드를 하나씩 둔다(예: 구독 안 한 점포). 시험 값은 코드 상수로 두고 "모의 데이터"라고 주석을 단다.
- 이 인터페이스는 백엔드 요청 문서 7.2절 1번과 맞춰 협의할 대상이다. 그 문서의 로그인 설명(점포 고유번호 + 대표 휴대폰 번호)은 이 태스크를 마친 뒤 고친다.

|---|---|---|

- 화면 문구는 기획자 답변 원문과 같은지 테스트로 확인한다.
- 로그와 테스트 출력에 비밀번호 · 점포코드 · 아이디 · PC 이름을 남기지 않는다.

## 8. 경계

- **항상**: 비밀번호는 PC에 저장하지 않는다. 로그 · 오류 보고에 입력값을 남기지 않는다 (`src/shared/log/`만 쓴다). 문구는 기획자 답변 원문 그대로.
- **먼저 묻기**: 새 라이브러리 · Tauri 플러그인 추가. 기획자 답변과 다른 동작.
- **하지 않기**: 실제 서버 주소 연결, PC에서 틀린 횟수 세기 · 잠그기, 비밀번호 · 점포코드 찾기 기능, 점포 선택 화면, 환경설정 화면 수정(T11의 함수 이름 한 줄 제외).

## 9. 완료 기준

1. 점포번호 계정(점포코드 + 비밀번호)과 웨일ERP 계정(아이디 + 비밀번호 + 점포코드)이 모의 서버에서 로그인된다 (화면 테스트).
2. 오류 6가지가 3.4의 문구로 보인다 (화면 테스트).
3. 점포번호 찾기 버튼 · 팝업이 없고, 안내 줄 2개가 각 탭에 보인다 (화면 테스트).
4. 로그인에 성공하면 점포코드를 기억하고, 다음 로그인 화면의 두 탭에 채워 둔다 (단위 + 화면 테스트).
5. 권한 표(2장)대로 `canEditSetting`이 답한다. 점포번호 계정으로 T11 프린터 설정을 바꿀 수 있다 (단위 테스트).
6. 자동 로그인 동작(성공 · 만료 · 네트워크 오류 · 로그아웃 시 삭제 · 프로그램 종료 시 유지)이 그대로 동작한다 (단위 테스트 + Windows 수동 확인).
7. 비밀번호가 PC 저장소와 로그에 남지 않는다 (테스트 또는 코드 확인).
8. ① lint · typecheck · format · test · build · Rust 검사 통과, ② · ③ 리뷰 완료.
