- **태스크**: T07 (Plane WHALEERPPO-8, `[F-HSTLST]`), 태스크 문서 `docs/tasks/T07-order-history.md` (기획자 답변 전에 쓴 것이라 이 스펙이 우선한다)
- **근거**: 화면정의서 v0.8 p.13 · p.14, 기획자 답변 Q17 · Q19 · Q27 · Q28 · Q29 · Q34 · Q35 · Q36 · Q37 · Q50 (`docs/tasks/planner-answers.md`), 백엔드 요청 문서 3.7 · 7장, 스펙 `SPEC-order-sync.md` · `SPEC-order-summary.md`, spec-store `whalepos` F-HSTLST · S-HLLIST · S-HLDETL

- **상태**: 승인 (2026-11-19, 사용자)

## 1. 목표

[주문내역] 탭에서 최근 한 달 주문을 기간 · 상태 · 검색으로 찾고, 한 건의 결제 정보와 처리 이력을 본다. 고객이 환불 · 주문을 문의할 때 매장이 바로 찾게 하는 화면이다.

- **이번 범위 밖**: 실제 인쇄 · 영수증 미리보기 팝업(T12, Q50), 한 달보다 앞선 내역(웨일ERP, Q34), 엑셀 내려받기(기획에 없음).

## 2. 주문내역 목록 (p.13)

### 2.1 기간 (Q34)

- 처음 열면 **오늘**.
- 바로가기 [오늘] [어제] [이번 달] [최근 한 달] + 달력(하루 또는 기간을 고르고 [확인]).
- 기간 옆 `<` `>`: 고른 기간 길이만큼 옮긴다(하루면 하루씩). 조회 범위 밖으로 가는 쪽은 흐리게 막는다.
- 조회 범위: 최근 한 달(한 달 전 같은 날 ~ 오늘, 하루 기준 PC 시계 0시). 달력에서 범위 밖 날짜는 고를 수 없고, 달력 아래에 「이전 내역은 웨일ERP에서 볼 수 있습니다.」.

### 2.2 검색 (Q36)

- 검색칸 안내: 「휴대폰 번호 끝 4자리 · 픽업번호 · 주문번호」. 픽업번호는 `#343` · `343` 모두.
- 검색은 고른 기간과 상관없이 최근 한 달 전체에서 찾는다. 검색 중에는 기간 위에 「최근 한 달에서 검색한 결과입니다」를 보인다(11장 A).
- 고객명 검색은 없다.

### 2.3 상태 탭 (Q17 · Q19 · Q35)

- 전체 / 접수대기 / 제조중 / 제조완료 / 픽업완료 / 취소. 탭마다 건수.
- 취소 탭에는 매장취소 · 고객취소가 함께 보이고 상태 글자로 구분한다.
- 요약 줄: 전체 탭 「총 9건 · 결제 합계 ₩26,100 (취소 1건 제외)」, 취소 탭 「총 N건 · 취소 금액 ₩…」, 그 밖의 탭 「총 N건 · 결제 합계 ₩…」. 금액은 결제금액(할인 뒤).

### 2.4 목록

| 열 | 내용 |
|---|---|
| 픽업번호 | `#12` |
| 고객 | 가린 이름 |
| 메뉴 | 「아메리카노 외 2개」 (첫 메뉴 + 나머지 메뉴 종류 수, T04와 같은 셈) |
| 금액 | 결제금액 |
| 상태 | 글자색: 접수대기 주황 · 제조중 파랑 · 제조완료 초록 · 픽업완료 검정 · 매장취소 / 고객취소 빨강 |
| 주문일시 | `11.17 13:21` |

- 정렬: 주문일시 최신이 위.
- 접수대기 행은 배경을 노랗게 강조한다.
- 행을 누르면 상세(3장)로 간다. 행 높이는 손가락으로 누르기 쉽게 44px 이상.
- 페이지: 페이지당 20 / 50(기본) / 100건, PC에 기억(Q37). 번호 · 이전 · 다음.
- 결과가 없으면 「조회된 주문이 없습니다.」.
- 목록을 불러오는 중에는 표시, 실패하면 「주문내역을 불러오지 못했습니다. [다시 시도]」.

## 3. 주문내역 상세 (p.14)

| 번호 | 영역 | 내용 |
|---|---|---|
| 1 | 머리 | [← 이전], 상태 글자, 픽업번호 |
| 2 | 주문 메뉴 | 메뉴명 · 단가 · 수량 · 금액, 옵션은 아래 들여쓰기(옵션 금액 있으면 함께), 합계 |
| 3 | 기본 정보 | 주문일시, 주문번호 16자리(Q28), 고객명(가림), 연락처 「***-****-1234」(T05와 같음), 픽업 예정, 「3번째 주문」 · 첫 주문이면 「첫 주문」 꼬리표(Q29) |
| 4 | 요청사항 | 있으면 노란 강조, 없으면 칸 없음 |
| 5 | 결제정보 | 주문금액, 할인 줄(프로모션 · 쿠폰 · 스탬프 · 포인트 중 쓴 것만, Q35), 결제금액, 결제수단, 결제시각, 거래번호 |
| 6 | 처리 이력 | 결제(주문) · 제조중 · 제조완료 · 픽업완료 시각(T05 statusTimes). 취소면 취소 시각 · 누가(매장취소 / 고객취소 / 자동 취소) · 사유 |
| 7 | 아래 버튼 | T05와 같은 상태별 버튼 규칙(Q27): 다음 단계 하나만 파란 강조, [주문취소]는 강조 없음. 취소 주문은 [영수증 인쇄](취소 영수증)만. 인쇄 버튼은 T12 전까지 회색으로 막음 → T12에서 연결함(2026-11-19, `SPEC-print-forms.md`) |

- [← 이전]으로 돌아가면 목록의 기간 · 탭 · 검색어 · 페이지 · 스크롤이 그대로다.
- 상태 버튼은 T03 `changeStatus` · T05 취소 사유 팝업을 그대로 쓴다. 성공하면 상세 · 목록의 그 주문이 새 상태로 바뀐다. 실패하면 「#12 …」 토스트.
- 접수대기 · 제조중 · 제조완료 주문은 [주문접수] 탭의 같은 주문과 한 상태를 보인다(11장 B).
- 상세를 불러오지 못하면 「주문 정보를 불러오지 못했습니다. [다시 시도]」.

## 4. 데이터 (가정, 백엔드 협의 전)

- 목록 · 상세는 서버에 묻는다(백엔드 요청 문서 3.7: 기간 · 상태 · 검색어 · 페이지 → 목록 · 탭별 건수 · 합계, 주문 한 건 → 결제 정보 포함 상세). 화면이 직접 걸러 세지 않는다.
- 모의 서버가 최근 한 달 예시 주문(날마다 몇 건, 상태 · 결제수단 · 할인 · 취소 사유 섞어서)을 만든다. 오늘 주문은 T03 모의 주문과 같은 것이다.
- 모든 요청 10초 제한(T03과 같음).
- 결제 정보 · 취소 정보 · 누적 주문 횟수 칸 이름은 가정이며 백엔드 요청 문서 7장과 맞춘다. 문서에 없는 칸이 필요하면 작업 세션이 보고하고 pos-boss가 문서에 더한다.

## 6. 로그

- 남길 것: 조회 실패(원인 요약), 상태 변경 결과(T03이 남김).
- 남기지 않을 것: 검색어(휴대폰 끝 4자리일 수 있음), 고객명 · 연락처 · 결제 정보 · 거래번호.

## 7. 테스트 전략

- 순수 함수: 바로가기 4개 기간, `<` `>` 이동과 범위 끝 막기, 달력 범위(한 달 전 같은 날, 월말 · 2월), 「외 N개」, 금액 표시, 요약 줄 3가지.
- 화면: 처음 오늘, 기간 · 탭 · 검색 · 페이지 바꾸면 서버에 맞는 조건으로 묻고 목록 · 건수가 바뀜, 검색 중 안내, 페이지당 건수 PC 기억, 빈 결과 · 실패 · 다시 시도, 행 → 상세 → 이전(조건 유지), 상세 영역 7개, 상태 버튼과 취소 팝업, 인쇄 버튼 막힘, 첫 주문 꼬리표.

## 8. 경계

- **항상**: 상태 변경은 `useOrders().changeStatus`로만. 개인정보는 서버가 가린 값만. 검색어를 로그에 남기지 않는다.
- **먼저 묻기**: 새 라이브러리(달력 포함), 스펙에 없는 열 · 버튼.
- **하지 않기**: 실제 인쇄, 한 달보다 앞선 조회.

## 9. 완료 기준

1. 처음 열면 오늘, 바로가기 · 달력 · `<` `>`가 2.1대로 움직이고 범위 밖은 고를 수 없다 (테스트).
2. 기간 · 탭 · 검색 · 페이지를 바꾸면 목록 · 건수 · 요약 줄이 맞게 바뀐다 (테스트).
3. 행을 누르면 상세가 3장대로 보이고, [← 이전]이면 목록 조건이 유지된다 (테스트).
4. 상세의 상태 버튼이 T05 규칙대로 보이고 동작하며, 인쇄 버튼은 막혀 있다 (테스트).
5. 1024 × 768에서 목록 · 상세가 잘리지 않고 터치로 다룰 수 있다 (Linux 실제 창 + Windows).
6. ① lint · typecheck · format · test · build · Rust 검사 통과, ② · ③ 리뷰 완료.

### 12.1 「환불」 상태 (T22, Q66 + 담당자 결정)

- 매장취소 · 고객취소(자동 취소 포함) 주문의 환불이 끝나면 상태가 **「환불」**이 된다. 「취소」 탭에 매장취소 · 고객취소와 같이 보이고, 상태 글자만 「환불」(빨강).
- 상세 처리 이력: 취소 시각 · 누가(매장취소 / 고객취소 / 자동 취소) · 사유에 **환불 시각**을 더한다.
- 금액은 **주문한 날**에 반영한다(Q66). 합계 규칙(HST-06)은 환불도 취소와 같이 본다: 전체 탭 합계에서 빼고 「(취소 N건 제외)」에 센다, 취소 탭 합계에 넣는다.
- 취소 영수증은 「환불」 주문에서도 뽑을 수 있다(취소 주문과 같음).
- 상세의 「N번째 주문」(HST-08)을 셀 때 「환불」도 매장취소 · 고객취소처럼 뺀다 (2026-11-25 사용자 결정).

### 12.2 자동 픽업완료 표시 (T22, Q65)

- 0시 서버 자동 픽업완료 주문은 목록의 상태 글자를 **「자동 픽업완료」**로, 상세 처리 이력의 픽업완료 줄에 「(자동)」을 붙인다. 「픽업완료」 탭에 같이 보인다.
- 상태 탭은 늘리지 않는다(전체 / 접수대기 / 제조중 / 제조완료 / 픽업완료 / 취소 그대로).

### 12.3 재제조 기록 (T21)

- 상세 처리 이력에 재제조마다 시각 · 사유 줄을 더한다(`SPEC-remake.md`).
