# 스펙: 프로그램 틀 · 헤더 · 창 제어 (`app-shell`)

- **태스크**: T01 (Plane WHALEERPPO-2), 태스크 문서 `docs/tasks/T01-app-shell-header.md`
- **근거**: 화면정의서 v0.8 p.4~6 (`docs/references/pickup-order-screen-spec-v0.8-260717.pdf`)
- **선행**: T00 프로젝트 골격
- **상태**: 승인 (2026-11-16, 사용자)

## 1. 목표

모든 화면이 올라갈 바탕을 만든다. 점원이 로그인하면 탭이 열리고, 헤더에서 주문받기를 켜고 끄며, 더보기 메뉴로 창을 다루고 로그아웃 · 종료할 수 있다.

- **사용자**: 매장 점원(바쁨, 클릭은 적게), 점주.
- **이번 범위 밖**: 각 탭의 내용(T04 이후), 로그인 화면 자체(T02), 픽업 상태 선택(Q02 답변 전), 트레이(Q05), 오류 · 끊김 · 업데이트 안내 화면(Q51), 바탕화면 위젯(T06).

## 2. 기능 요구사항

### 2.1 화면 틀

| 영역 | 로그인 전 | 로그인 후 |
|---|---|---|
| 헤더 왼쪽 | 로고 "P" + "픽업오더 주문접수" | 같음 |
| 주문받기 토글 | 숨김 | 표시 (ON 초록 / OFF 회색) |
| 헤더 오른쪽 | 점포 아이콘 + "로그인 후 이용해주세요." | 점포 아이콘 + 점포명 |
| 더보기(⋮) | 표시 | 표시 |
| 탭 | 숨김 | 주문접수 · 주문내역 · 매장정보 · 메뉴품절 · 환경설정 |
| 콘텐츠 | 로그인 화면 자리 (T02가 채움) | 고른 탭의 화면 자리 (빈 화면 + 탭 이름) |

- 로그인 후 처음 보이는 탭은 **주문접수**다 (p.8 "로그인 성공 시 주문접수 화면으로 이동").
- 탭 이동은 라우터 없이 화면 상태로 한다. 데스크톱 프로그램이라 주소창이 없고, 라이브러리를 늘리지 않기 위해서다.
- 환경설정 탭 안의 하위 탭(위젯설정 · 프린터설정 · AI챗봇 인기메뉴 설정)은 이번에는 이름만 있는 빈 화면이다.

### 2.2 주문받기 토글

1. 로그인 직후 기본값은 **OFF**다 (p.5). 재실행 때 이어 갈지는 Q03 답변 전이라 매번 OFF로 시작한다.
2. OFF → ON: 확인 없이 바로 서버에 "주문 받음"을 보낸다. 성공하면 ON으로 바꾼다.
3. ON → OFF: 확인 팝업을 띄운다. [주문 중단]을 누르면 서버에 "주문 중단"을 보내고, 성공하면 OFF로 바꾼다. [취소]면 그대로 둔다.
   - 제목 "주문 수신을 중단하시겠습니까?"
   - 본문 "주문 수신이 중단되면 고객은 앱에서 주문을 할 수 없습니다."
   - 버튼 [취소] [주문 중단]
4. 서버 요청이 진행 중일 때는 토글을 다시 누를 수 없다 (두 번 보내기 방지).
5. 서버 요청이 실패하면 토글을 바꾸지 않고 짧은 오류 안내를 띄운다. 임시 문구: "서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요." (화면정의서에 없음, 사용자 결정 2026-11-16)

### 2.3 더보기 메뉴

| 버튼 | 동작 | 확인 팝업 |
|---|---|---|
| 창 최소화 | 창을 작업표시줄로 내린다 | 없음 |
| 창 줄이기 | 기본 크기로 줄이고 화면 정가운데에 둔다. 기본 크기 임시값 **1280×800** (Q07 답변 전, 사용자 결정 2026-11-16) | 없음 |
| 창 늘리기 | 화면 전체 크기로 키운다 (최대화) | 없음 |
| 시스템종료 | 주문받기를 OFF로 보낸 뒤 로그아웃하고 프로그램을 끝낸다 | 제목 "시스템을 종료하겠습니까?" / 본문 "주문 수신이 자동으로 중단됩니다." / [취소] [시스템 종료] |
| 로그아웃 | 주문받기를 OFF로 보낸 뒤 로그아웃하고 로그인 화면으로 간다 | 제목 "로그아웃 하시겠습니까?" / 본문 "주문 수신이 자동으로 중단됩니다." / [취소] [로그아웃] |

- 로그인 전에는 로그아웃 버튼을 숨긴다. 로그인 전 시스템종료는 확인 팝업 없이 바로 끝내지 않고, 같은 팝업을 띄운다 (실수로 누르는 것 방지).
- 시스템종료 · 로그아웃에서 "주문 중단" 요청이 실패해도 로그아웃과 종료는 진행한다. 점원이 프로그램을 못 끄는 상황을 막기 위해서다. 이때 서버에는 점포가 "주문 받음"으로 남을 수 있으며, 이 문제는 백엔드 요청 문서 7.3절 13번(신호가 끊긴 점포 처리)에서 다룬다.
- "시스템종료"는 프로그램만 끝낸다. PC는 끄지 않는다 (Q06 답변 전 가정).

### 2.4 창

- **Windows 기본 제목 표시줄을 없앤다** (화면정의서 그림대로, 사용자 결정 2026-11-16). 그래서 헤더를 끌어 창을 옮길 수 있어야 하고, 헤더 안의 버튼 · 토글 · 더보기는 끌기 영역에서 빼야 한다. 방법은 구현 때 Tauri v2 공식 문서로 확인한다.
- 기본 제목 표시줄이 없으므로 창 닫기는 더보기의 시스템종료로만 한다. Alt+F4 등 운영체제 닫기 동작을 받으면 시스템종료와 같은 확인 팝업을 띄운다. (가정. Tauri에서 막을 수 있는지 구현 때 확인하고, 안 되면 보고한다)
- 시작 크기는 "창 줄이기"의 기본 크기와 같다.

## 3. 데이터 · 외부 연동 (가정, 백엔드 협의 전)

백엔드 API가 없으므로 아래 인터페이스 뒤에 **모의 구현**을 둔다. 실제 API가 정해지면 구현만 바꾼다.

```ts
// src/shared/api/store-status.ts
export interface StoreStatusApi {
  /** 점포의 주문 받기 상태를 바꾼다. 실패하면 예외를 던진다. */
  setAcceptingOrders(accepting: boolean): Promise<void>;
}
```

- 모의 구현은 기본 300ms 뒤 성공한다. 테스트에서 실패를 만들 수 있어야 한다.
- 로그인 상태(로그인 여부, 점포명, 계정 종류)는 T02가 만든다. T01은 우선 모의 로그인 상태로 화면을 바꿔 볼 수 있게 한다.
- 창 제어는 Tauri 창 API를 `src/shared/platform/window.ts` 한 곳에서 감싼다. 화면 코드는 Tauri를 직접 부르지 않는다. 테스트와 브라우저 개발 모드(`pnpm dev`)에서는 아무 일도 하지 않는 구현으로 바꾼다.
- 필요한 Tauri 창 권한(최소화, 크기 · 위치, 최대화, 닫기)은 구현할 때 Tauri v2 공식 문서로 확인해 최소한만 연다.

## 4. 명령어

T00이 끝나면 `AGENTS.md` "기술 스택 / 명령어"에 적힌 명령을 그대로 쓴다. T00 지시서 기준 예정 명령:

```
pnpm dev            # 브라우저에서 화면 개발
pnpm tauri dev      # 데스크톱 창으로 실행 (Linux 시스템 패키지 필요)
pnpm test           # Vitest
pnpm lint           # ESLint
pnpm typecheck      # tsc
pnpm format:check   # Prettier
pnpm build          # 화면 빌드
```

## 6. 코드 스타일

`AGENTS.md` "개발 규칙"을 따른다. 예:

```tsx
// 주문 중단은 고객 주문을 막으므로 반드시 확인을 받는다 (화면정의서 p.5)
export function OrderAcceptToggle({ accepting, pending, onRequestChange }: Props) {
  return (
    <button
      type="button"
      role="switch"
      aria-checked={accepting}
      disabled={pending}
      onClick={() => onRequestChange(!accepting)}
      className="flex items-center gap-2 text-lg"
    >
      주문 받기 <span>{accepting ? "ON" : "OFF"}</span>
    </button>
  );
}
```

## 7. 테스트 전략

| 수준 | 대상 | 도구 |
|---|---|---|
| 단위 | 토글 상태 변화(요청 중 잠금, 실패 시 원상태) | Vitest |
| 화면 | 로그인 전/후 헤더 · 탭, 팝업 문구, 팝업 [취소] 동작, 탭 전환 | React Testing Library |
| 수동 | 창 최소화 · 줄이기 · 늘리기 · 종료, 헤더 끌어서 창 옮기기, Alt+F4 (Tauri 창에서만 가능) | Windows에서 사용자 확인 체크리스트 |

- 팝업 문구는 화면정의서 원문과 글자 하나까지 같은지 테스트로 확인한다.
- 창 제어는 감싼 모듈을 가짜로 바꿔 "어떤 함수가 불렸는지"만 테스트한다.

## 8. 경계

- **항상**: 팝업 문구는 화면정의서 원문 그대로. 서버 요청 성공 뒤에만 토글을 바꾼다. 화면 코드에서 Tauri를 직접 부르지 않는다.
- **먼저 묻기**: 허용 목록 밖의 라이브러리 추가(상태 관리, 라우터, 아이콘 등). 화면정의서와 다른 동작. 임시값을 확정값으로 바꾸는 것.
- **하지 않기**: 픽업 상태 선택 만들기(Q02 전), 트레이 만들기(Q05 전), 탭 안의 기능 화면 만들기.

## 9. 완료 기준

1. 로그인 전/후에 헤더와 탭이 p.5 상태 ①②③대로 바뀐다 (화면 테스트).
2. 로그인 직후 토글이 OFF다. ON은 확인 없이, OFF는 확인 팝업 뒤에 바뀐다. 요청 중에는 다시 누를 수 없고, 실패하면 원래 상태로 남는다 (테스트).
3. 토글 OFF · 로그아웃 · 시스템종료 팝업의 문구가 기획서와 같다 (테스트).
4. 탭 5개와 환경설정 하위 탭 3개 사이를 오갈 수 있다 (테스트).
5. 로그아웃하면 로그인 화면으로 돌아가고, 그 전에 "주문 중단" 요청을 보낸다 (테스트).
6. 창 최소화 · 줄이기 · 늘리기 · 종료, 헤더 끌기가 Tauri 창에서 동작한다 (Windows 수동 확인 체크리스트).
7. ① lint · typecheck · test · build 통과, ② · ③ 리뷰 완료.

## 10. 화면정의서와 다르게 하거나 추가한 것

| 항목 | 화면정의서 | 이 스펙 | 이유 |
|---|---|---|---|
| 로그인 전 시스템종료 | 정의 없음 | 같은 확인 팝업 | 실수 방지 |
| 주문 중단 요청 실패 시 로그아웃 · 종료 | 정의 없음 | 그대로 진행 | 프로그램을 못 끄는 상황 방지 |
| 토글 요청 실패 | 정의 없음 | 토글 유지 + 오류 안내 | 화면과 서버 상태가 어긋나지 않게 |
| 운영체제 닫기(Alt+F4) | 정의 없음 | 시스템종료 확인 팝업 | 주문 중단 없이 꺼지는 것 방지 |
