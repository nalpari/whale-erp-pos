# 스펙: 프로그램 틀 · 헤더 · 창 제어 (`app-shell`)

- **태스크**: T01 (Plane WHALEERPPO-2), 태스크 문서 `docs/tasks/T01-app-shell-header.md`
- **근거**: 화면정의서 v0.8 p.4~6 (`docs/references/pickup-order-screen-spec-v0.8-260717.pdf`), 기획자 답변 Q02~Q08 · Q51 (`docs/tasks/planner-answers.md`), spec-store `whalepos` F-SHLWIN · F-ACPTOG. **화면정의서와 다르면 기획자 답변을 따른다.**
- **선행**: T00 프로젝트 골격
- **상태**: 승인 (2026-11-18, 사용자, 개정판). 처음 판은 2026-11-16 승인. 바뀐 점은 12장

## 1. 목표

모든 화면이 올라갈 바탕을 만든다. 점원이 로그인하면 탭이 열리고, 헤더에서 주문받기를 켜고 끄며, 더보기 메뉴로 창을 다루고 다시시작 · 로그아웃 · 프로그램 종료를 할 수 있다.

- **사용자**: 매장 점원(바쁨, 클릭은 적게, 터치 우선), 점주.
- **이번 범위 밖**: 각 탭의 내용(T04 이후), 로그인 화면(T02), 픽업 상태 선택(Q02로 Lite 범위에서 제외), 트레이(Q05로 두지 않음), 업데이트 안내(T15), 바탕화면 위젯(T06), 서버가 주문받기를 자동으로 끌 때의 띠 · 위젯 안내(Q53 · Q54, 주문 수신 T03). 연결 끊김 띠 · 경고음과 [새로고침] 메뉴(13장 C · D)도 T03으로 넘긴다.

## 2. 기능 요구사항

### 2.1 화면 틀

| 영역 | 로그인 전 | 로그인 후 |
|---|---|---|
| 헤더 왼쪽 | 로고 "P" + "픽업오더 주문접수" | 같음 |
| 주문받기 토글 | 숨김 | 표시 (ON 초록 / OFF 회색) |
| 헤더 오른쪽 | 점포 아이콘 + "로그인 후 이용해주세요." | 점포 아이콘 + 점포명 |
| 더보기(⋮) | 표시 | 표시 |
| 탭 | 숨김 | 주문접수 · 주문내역 · 매장정보 · 메뉴품절 · 환경설정 |
| 콘텐츠 | 로그인 화면 | 고른 탭의 화면 |

- 로그인 후 처음 보이는 탭은 **주문접수**다.
- 헤더에 픽업 상태(여유 · 보통 · 혼잡)는 두지 않는다 (기획 결정, Q02).

### 2.2 주문받기 토글

1. 프로그램을 켤 때마다(자동 로그인 · [다시시작] 포함) **OFF로 시작**한다. 마지막 상태를 이어 가지 않는다 (Q03). 창 제어 · [새로고침] · 다른 창 뒤로 가는 경우는 상태를 유지한다.
2. OFF → ON: 확인 없이 서버에 "주문 받음"을 보낸다. 성공하면 ON.
3. ON → OFF: 확인 팝업 → [주문 중단]이면 서버에 "주문 중단"을 보내고 성공하면 OFF.
   - 제목 "주문수신을 중단하시겠습니까?" / 본문 "주문 수신이 중단되면 고객은 앱에서 주문을 할 수 없습니다." / [취소] [주문 중단]
4. 요청 중에는 토글을 다시 누를 수 없다.
5. 서버 요청이 실패하면 토글을 바꾸지 않고 토스트 "처리하지 못했습니다. 잠시 뒤 다시 시도해 주세요." 를 보인다 (Q51 ②). 토스트는 T11에서 만든 공용 `Toast`를 쓴다.
6. OFF는 새 주문만 막는다. 이미 받은 주문은 OFF에서도 처리한다 (Q04, T04 이후 화면이 따른다).

### 2.3 처리할 주문 경고 (Q04)

주문받기 OFF · [다시시작] · [로그아웃] · [프로그램 종료] 확인창에, **처리할 주문(접수대기 · 제조중 · 제조완료)이 1건 이상이면** 경고 한 줄을 더한다. 0건이면 줄 없이 원래 확인창 그대로다. 경고 줄 기능은 지금 만들고, 건수는 T03이 채울 때까지 0을 돌려주는 자리(함수 하나)로 둔다. 그래서 T03 전에는 경고 줄이 보이지 않는다 (13장 A).

| 확인창 | 원래 문구 | 더하는 경고 |
|---|---|---|
| 주문받기 OFF | (2.2-3) | 처리할 주문이 N건 있습니다. 주문받기를 꺼도 이 주문은 처리해야 합니다. |
| 다시시작 | 제목 "다시시작하시겠습니까?" / 본문 "다시 켜면 주문받기가 꺼집니다." | 처리할 주문이 N건 있습니다. 다시 켜도 이 주문은 그대로 처리할 수 있습니다. |
| 로그아웃 | 제목 "로그아웃 하시겠습니까?" / 본문 "주문 수신이 자동으로 중단됩니다." | 처리할 주문이 N건 있습니다. 프로그램을 끄면 이 주문을 처리하거나 고객에게 알림을 보낼 수 없습니다. |
| 프로그램 종료 | 제목 "프로그램을 종료하시겠습니까?" / 본문 "주문 수신이 자동으로 중단됩니다." | 로그아웃과 같음 |

### 2.4 더보기 메뉴 (Q05 · Q06)

토스POS처럼 더보기(⋮) 안에 **아이콘 칸**으로 둔다. 손가락으로 누르기 좋게 칸마다 아이콘 + 글자.

| 메뉴 | 하는 일 | 주문받기 | 다음에 켤 때 | 확인창 |
|---|---|---|---|---|
| 다시시작 | 주문받기를 OFF로 보낸 뒤 프로그램을 껐다 다시 켠다. 화면이 멈췄을 때 쓴다 | OFF | 자동 로그인(켜 둔 경우) | 있음 (2.3) |
| 로그아웃 | 주문받기를 OFF로 보낸 뒤 로그인 화면으로. **자동 로그인 해제** | OFF | 로그인 화면 | 있음 (2.3) |
| 프로그램 종료 | 주문받기를 OFF로 보낸 뒤 프로그램을 끈다. PC는 끄지 않는다. 자동 로그인은 유지. **빨간 아이콘** | OFF | 자동 로그인(켜 둔 경우) | 있음 (2.3) |
| 창 최소화 | 작업표시줄로 내린다. 프로그램 · 알림 · 주문받기는 그대로 | 유지 | - | 없음 |
| 창 늘리기 / 창 줄이기 | 화면 전체로 / 기본 크기(1280 × 800, 화면이 작으면 작업표시줄을 뺀 화면 크기. 단 1024 × 768보다 작게 하지 않는다)로 줄여 가운데에. 지금 상태에 따라 하나만 보인다 | 유지 | - | 없음 |
| 로그 확인 | 2026-11-17 T14에서 넣은 개발 추가 메뉴. 그대로 둔다 | 유지 | - | 없음 |

- 로그인 전에는 로그아웃을 숨긴다. 로그인 전 프로그램 종료도 같은 확인창을 띄운다.
- "주문 중단" 요청이 실패해도 다시시작 · 로그아웃 · 종료는 진행한다 (서버가 1분 무응답이면 자동으로 끈다, Q53).
- 「시스템종료」라는 이름은 쓰지 않는다 (Q06).
- [새로고침](Q05)은 다시 불러올 주문 목록이 생기는 T03에서 메뉴에 넣는다 (13장 D).

### 2.5 창 (Q07 · Q08)

- Windows 기본 제목 표시줄과 [×]는 두지 않는다. 종료는 [프로그램 종료]로만 한다.
- 헤더 빈 곳을 끌면 창이 옮겨지고, 두 번 누르면 창 늘리기 / 줄이기가 바뀐다 (보조 동작. 같은 일을 더보기 메뉴로도 할 수 있어야 한다, 터치 우선 규칙).
- 창 테두리를 끌어 크기를 바꿀 수 있다. **최소 크기 1024 × 768** (이보다 작게 줄일 수 없다). 기획자 답(Q07 · Q08)은 1024 × 700이었으나 사용자가 4:3 모니터 표준 해상도인 1024 × 768로 바꿨다 (2026-11-18). 1024 × 768 화면에서는 창이 작업표시줄을 덮는다.
- **지원하는 가장 작은 화면은 1024 × 768이다** (Q07, 2026-11-18 사용자). 이보다 작은 화면은 지원하지 않고 사용을 권하지 않는다. 그런 화면을 위한 처리(창 줄이기 때 최대화 등)는 만들지 않는다.
- **처음 설치해 켤 때는 화면 전체**로 연다. 그 뒤로는 **마지막 창 크기 · 위치를 그 PC에 기억**해 다음 실행 때 그대로 연다 (Q07 · Q15). 라이브러리 없이 직접 만든다: 창을 옮기거나 크기를 바꾸면 크기 · 위치 · 최대화 여부를 PC에 저장하고, 시작할 때 되살린다. 저장값이 최소 크기보다 작거나 지금 모니터 밖이면 버리고 기본(화면 전체)으로 연다 (13장 B).
- Alt + F4, 작업표시줄 아이콘 우클릭 → [창 닫기]로 끄려 해도 바로 꺼지지 않고 [프로그램 종료]와 같은 확인창(2.3 경고 포함)을 띄운다.

### 2.6 연결 끊김 안내 (Q51 ①)

- 인터넷이 끊기면 헤더 아래 빨간 띠 "인터넷 연결이 끊겼습니다. 새 주문을 받을 수 없습니다. 다시 연결하는 중…" 과 경고 알림음. 다시 연결되면 띠를 지우고 주문받기를 끊기기 직전 상태로 둔다. **서버 연결 상태를 아는 T03에서 만든다** (13장 C). T01에서는 만들지 않는다.

## 3. 데이터 · 외부 연동 (가정, 백엔드 협의 전)

```ts
// src/shared/api/store-status.ts (기존)
export interface StoreStatusApi {
  setAcceptingOrders(accepting: boolean): Promise<void>;
}
```

- 모의 구현 그대로 쓴다. 로그인 상태는 T02가 만든 것을 쓴다.
- 창 제어 · 다시시작은 `src/shared/platform/window.ts` 한 곳에서 감싼다. 화면 코드는 Tauri를 직접 부르지 않는다.
- **다시시작**은 Tauri 기본 기능(`AppHandle::restart` 등, 구현 때 Tauri v2 공식 문서로 확인)으로 한다. 새 플러그인이 필요하면 멈추고 보고한다.
- 필요한 Tauri 창 권한은 구현 때 공식 문서로 확인해 최소한만 연다.

## 8. 경계

- **항상**: 확인창 문구는 원문 그대로. 서버 요청 성공 뒤에만 토글을 바꾼다. 화면 코드에서 Tauri를 직접 부르지 않는다.
- **먼저 묻기**: 새 라이브러리 · Tauri 플러그인. 기획자 답변과 다른 동작.
- **하지 않기**: 픽업 상태, 트레이, 업데이트 안내, 서버 자동 OFF 안내 · 연결 끊김 띠 · 새로고침(T03), 탭 안의 기능 화면.

## 9. 완료 기준

1. 로그인 전/후 헤더와 탭이 2.1대로 바뀐다 (화면 테스트).
2. 프로그램을 켜면 주문받기는 OFF다. ON은 확인 없이, OFF는 확인창 뒤에 바뀐다. 실패하면 그대로 남고 토스트가 뜬다 (테스트).
3. 처리할 주문이 있으면 OFF · 다시시작 · 로그아웃 · 종료 확인창에 경고 줄이 붙고, 0건이면 붙지 않는다 (테스트).
4. 더보기 메뉴가 아이콘 칸으로 2.4의 메뉴(새로고침 제외)를 보이고, 「시스템종료」 대신 「프로그램 종료」(빨간 아이콘)다 (화면 테스트).
5. 다시시작이 "주문 중단"을 보낸 뒤 프로그램을 다시 켜고, 다시 켜진 뒤 자동 로그인 · 주문받기 OFF다 (테스트 + Windows 수동).
6. 최소 1024 × 768, 첫 실행 화면 전체, 재실행 시 마지막 크기 · 위치, Alt + F4 · [창 닫기] 확인창이 동작한다 (Windows 수동).
7. ① lint · typecheck · format · test · build · Rust 검사 통과, ② · ③ 리뷰 완료.
