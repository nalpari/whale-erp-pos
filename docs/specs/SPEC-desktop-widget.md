# 스펙: 바탕화면 주문 알림 위젯 · 알림음 (`desktop-widget`)

- **태스크**: T06 (Plane WHALEERPPO-7, `[F-WDGPOP]`), 태스크 문서 `docs/tasks/T06-desktop-widget.md` (기획자 답변 전에 쓴 것이라 이 스펙이 우선한다)
- **근거**: 화면정의서 v0.8 p.7(위젯) · p.18(위젯설정) · p.24(반복 알림), 기획자 답변 Q05 · Q19 · Q20 · Q30 · Q31 · Q32 · Q33 · Q44 · Q54 (`docs/tasks/planner-answers.md`), 스펙 `SPEC-order-sync.md` · `SPEC-order-board.md` · `SPEC-order-summary.md`, spec-store `whalepos` F-WDGPOP · S-WPSHOW
- **선행**: T03 주문 수신, T04 주문접수 화면, T05 요약 · 취소 팝업
- **상태**: 승인 (2026-11-19, 사용자)

## 1. 목표

프로그램 창이 최소화됐거나 기존 POS 같은 다른 창 뒤에 있어도 새 주문을 놓치지 않게, 바탕화면 구석의 작은 창(위젯)과 알림음으로 알린다. 주문 누락 0건 원칙의 마지막 단계다.

- **이번 범위 밖**: 위젯 설정 화면(표시 상태 · 위치 · 크기 슬라이더 · 미리듣기, T10), 출력 실패 경고음 호출(T12), 실제 매장 스피커 크기 확인(사용자 실물 확인).

## 2. 알림음 (Q20 · Q44)

| 소리 | 울리는 때 |
|---|---|
| 새 주문 | 새 주문이 들어올 때 한 번. 접수대기 주문이 하나라도 있으면 30초마다 반복. 고객 취소 배너 때 한 번(T04가 이미 부름). 서버 자동 OFF 때 한 번(T03이 이미 부름) |
| 경고 | 인터넷 끊김(T03이 이미 부름), 출력 실패(T12) |

- 반복은 접수대기 주문이 모두 접수 · 취소되면 멈춘다. 주문받기 OFF여도 남은 접수대기가 있으면 계속한다 (Q04 · Q20).
- 같은 순간 새 주문 여러 건이 오면 한 번만 울린다.
- 두 소리는 서로 다르게 들려야 한다 (Q44). 소리 만드는 법은 11장 A.
- 크기는 11장 B. 크기 설정(최소 20%)은 T10.
- 30초 · 15분은 운영해 보고 조정할 값이므로 상수 하나로 둔다.

## 3. 위젯 창

### 3.1 창 성질

- 본 창과 다른 별도 창. 테두리 없음, 항상 위, 작업표시줄에 따로 나타나지 않음.
- 뜰 때 **키보드 초점을 빼앗지 않는다**. 기존 POS에서 금액을 입력하던 중에 위젯이 떠도 입력이 위젯으로 가면 안 된다.
- 위치: 화면 오른쪽 아래(작업표시줄 위), 여백 16px (11장 E). 위치 바꾸기는 T10.
- 폭 약 340px. 높이는 카드 수에 맞추고 화면 높이를 넘지 않는다.
- 본 창이 꺼지거나 로그아웃하면 위젯도 닫힌다.
- 구현 전에 Tauri v2 공식 문서로 창 만들기 · 항상 위 · 작업표시줄 숨김 · 초점 안 빼앗기 · 창 위치 · 창끼리 주고받기 방법과 필요한 권한(capabilities)을 확인하고, 확인한 문서 주소를 보고에 적는다. 공식 문서로 안 되는 것이 있으면 멈추고 보고한다.

### 3.2 언제 뜨나 (Q30 · p.7 ①)

| 상황 | 동작 |
|---|---|
| 새 주문이 옴 + 본 창이 앞에 있음(초점 있음, 최소화 아님) | 위젯은 띄우지 않고 알림음만 |
| 새 주문이 옴 + 본 창이 최소화됐거나 초점이 없음 | 위젯을 띄운다(이미 떠 있으면 카드만 더함) + 알림음 |
| 30초 반복 때 + 본 창이 앞에 있지 않음 | 숨겨 둔 위젯 · 닫은 접수대기 카드를 다시 띄운다 + 알림음 |
| 위젯이 떠 있는데 본 창을 앞으로 가져옴 | 11장 D |
| 보일 카드가 0장 | 위젯을 숨긴다 |

- 다시 켤 때 이미 있던 주문에는 새 주문 신호가 없다(T03 11장 G). 그래도 접수대기가 있으면 30초 반복이 위젯을 띄운다.

### 3.3 카드 (p.7 · Q31 · Q33)

| 줄 | 내용 |
|---|---|
| 머리 | 상태 글자(접수대기 · 제조중 · 제조완료) + 색, 오른쪽 위 [×] |
| 시간 | 「주문시간 13:21 \| 지금 픽업」 (픽업 예정 문구는 T04 함수 재사용), 픽업번호 `#12` |
| 요청사항 | 있으면 노란 바탕 1줄 말줄임 |
| 메뉴 | 메뉴명 · 수량 2줄까지, 넘으면 「+ 외 N개」 |
| 버튼 | 접수대기 [주문취소] [주문접수★] · 제조중 [제조완료★] · 제조완료 [픽업완료★] (Q33, 인쇄 버튼 없음) |

- 보일 상태: 접수대기는 늘 보인다. 제조중 · 제조완료는 11장 C. 픽업완료 · 취소 주문은 보이지 않는다.
- 순서: 접수대기를 먼저(오래된 주문이 위), 남는 자리에 제조중 · 제조완료(오래된 주문이 위).
- 최대 5장, 화면 높이에 들어가는 만큼. 넘으면 맨 아래 「+ N건 더 있음」 줄, 누르면 본 창을 앞으로 가져와 [주문접수] 첫 탭을 연다.
- 위젯 머리: 「새 주문 알림」 + 전체 닫기 [×].
- **자동 OFF 안내 카드 (Q54)**: 서버가 미접수 자동 취소 연속 2건으로 주문받기를 껐을 때, 주문 카드들 맨 위에 빨간 안내 카드 「접수하지 않은 주문 2건이 자동 취소되어 주문받기가 꺼졌습니다. 주문을 받으려면 주문받기를 켜 주세요.」(T03 문구 그대로)를 띄운다. 뜨는 조건은 새 주문과 같다(본 창이 앞이면 위젯 없이 띠 · 알림음만). 주문받기를 켜면 사라지고, 카드 [×]로 닫을 수 있다(다시 뜨지 않음). 카드를 누르면 본 창을 앞으로 가져온다. 5장 셈에는 넣지 않는다.
- 버튼 높이 44px 이상.

### 3.4 위젯에서 누르면 (Q30 · Q32 · Q33)

| 누른 것 | 동작 |
|---|---|
| [주문접수] · [제조완료] | 바로 처리 (T03 `changeStatus`, 본 창 카드도 같이 바뀜). 주문서는 이 PC에서 출력(T12) |
| [픽업완료] | 처리 성공 뒤 그 카드 자리에 「픽업완료 [완료 취소(05)]」가 5초 보이고 사라진다. 5초 안에 [완료 취소]면 제조완료로 돌아온다 (T03 되돌리기) |
| [주문취소] | 본 창을 앞으로 가져와(최소화면 되살림) T05 취소 사유 팝업을 띄운다 |
| 카드(버튼 · [×] 밖) | 본 창을 앞으로 가져와 [주문접수] 첫 탭에서 그 주문의 요약 팝업을 연다. 팝업을 닫으면 그 카드가 보이게 화면을 옮긴다 |
| 카드 [×] | 그 카드만 숨긴다. 접수대기 카드는 다음 30초 반복 때 다시 뜬다. 다른 상태 카드는 다시 뜨지 않는다 |
| 머리 [×] | 위젯 전체를 숨긴다. 다음 새 주문이나 30초 반복 때 다시 뜬다 |

- 요청 중에는 그 카드 버튼을 막는다.
- 실패하면 11장 F.
- 주문 상태가 바뀌면(본 창 · 다른 PC · 서버) 카드가 따라 바뀌거나 사라진다. 고객 취소면 카드가 사라지고, 배너 · 알림음은 T04 그대로 (Q19).

## 4. 구조

| 파일 | 역할 |
|---|---|
| `src/features/desktop-widget/` | 위젯 화면(카드 목록 · 카드), 위젯 판단 순수 함수(보일 카드 · 순서 · 5장 자르기 · 뜰지 말지) |
| `src/shared/sound/` | 실제 소리 재생 (지금의 빈 재생기를 바꿈), 30초 반복 |
| 본 창 쪽 연결 | 위젯 창 열기 · 숨기기, 위젯에 보일 주문 보내기, 위젯에서 온 동작을 `changeStatus` · 요약 팝업 · 취소 팝업으로 잇기 |
| `src-tauri/capabilities/` | 위젯 창 권한 (필요한 것만) |

- 주문 목록은 지금처럼 본 창 하나가 가진다(T03). 위젯은 본 창이 보내 준 목록을 보이기만 하고, 누른 동작은 본 창으로 돌려보낸다. 위젯이 서버에 직접 묻지 않는다(같은 주문을 두 군데서 따로 받으면 어긋날 수 있다).
- 새 라이브러리 없음. Tauri 공식 API만.
- 개발용 모의 주문 패널로 위젯을 시험할 수 있어야 한다(본 창을 최소화한 뒤 몇 초 뒤 주문이 오게 하는 버튼 등, 필요하면 더한다).

## 5. 로그

## 6. 테스트 전략

- 순수 함수: 보일 카드(상태 · 숨긴 카드), 순서(접수대기 먼저 · 오래된 것 위), 5장과 「+ N건」, 뜰지 말지(본 창 앞 · 최소화 · 초점 없음), 30초 반복 시작 · 멈춤, 같은 순간 여러 건이면 소리 한 번.
- 화면: 카드 버튼별 동작, 픽업완료 5초 · 완료 취소, 카드 [×] · 머리 [×]와 다시 뜨는 조건, 실패 표시.
- 창 · 소리는 가짜(테스트용) 창 · 재생기로 호출만 시험한다.
- 실제 창 성질(항상 위 · 작업표시줄 · 초점 · 위치)과 소리는 사람이 확인한다 (7장 5 · 6).

## 7. 완료 기준

1. 본 창이 앞에 있으면 새 주문에 알림음만, 최소화 · 다른 창 뒤면 위젯 + 알림음 (테스트 + 실제 창).
2. 접수대기가 있으면 30초마다 알림음이 반복되고, 모두 처리하면 멈춘다 (테스트).
3. 위젯 카드가 3.3대로 보이고(순서 · 최대 5장 · 「+ N건」), 3.4대로 동작한다. 위젯에서 처리하면 본 창 카드도 바뀐다 (테스트).
4. 카드 [×] · 머리 [×] 뒤 다시 뜨는 조건이 3.4와 같다 (테스트).
5. Linux 실제 창: 위젯이 오른쪽 아래에 항상 위로 뜨고, 작업표시줄에 따로 안 보이고, 다른 창에서 글자를 치던 중 떠도 입력이 위젯으로 가지 않는다 (사용자).
6. Windows: 기존 POS가 전체 화면일 때도 위젯이 보이는지, 매장 스피커에서 소리가 충분히 큰지 (사용자 실물 확인).
7. ① lint · typecheck · format · test · build · Rust 검사 통과, ② · ③ 리뷰 완료.
