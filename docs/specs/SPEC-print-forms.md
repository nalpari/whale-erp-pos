- **태스크**: T12 (Plane WHALEERPPO-13, `[F-PRTFRM]`), 태스크 문서 `docs/tasks/T12-print-forms.md` (기획자 답변 전에 쓴 것이라 이 스펙이 우선한다)
- **근거**: 화면정의서 v0.8 p.22 · p.23, 기획자 답변 Q13 · Q27 · Q33 · Q35 · Q44 · Q45 · Q47 · Q49 · Q50 (`docs/tasks/planner-answers.md`), 프린터설정 스펙 `SPEC-settings-printer.md`, 주문 동기화 `SPEC-order-sync.md`, spec-store `whalepos` F-PRTFRM · S-PFORDR · S-PFRCPT · S-PFFAIL
- **선행**: T11 프린터설정(슬롯 · 시험 인쇄 · Windows 드라이버 출력), T03 주문 동기화(`onAccepted` 신호), T04 · T05 · T07(인쇄 버튼 자리 · 아래 배너 쌓기)
- **상태**: 승인 (2026-11-19, 사용자)

## 1. 목표

[주문접수]를 누르면 주문서를 자동으로 뽑고, 요약 팝업 · 주문내역 상세에서 주문서 · 영수증을 다시 뽑는다. 출력에 실패해도 접수는 그대로 두고 알린다.

- **이번 범위 밖**: 프린터 상태(용지 없음 · 덮개 열림) 직접 읽기, ESC/POS 포트 직접 출력, 컵 라벨, 세금 증빙 양식 여부 판단.

## 2. 출력 방식

- T11 시험 인쇄와 같은 **Windows 프린터 드라이버 출력**(GDI, 맑은 고딕)을 쓴다. 사무실 SEWOO SLK-TS100에서 한글 출력을 확인했다(2026-11-18). 방식은 11장 A.
- 출력물은 화면(TS)이 "줄 목록"(글자 · 크기 · 굵게 · 정렬 · 구분선)으로 만들고, Rust가 그대로 그린다. 같은 줄 목록으로 영수증 미리보기도 그린다.
- 용지 폭은 그 슬롯의 설정(58 / 80mm, T11)을 따른다. 긴 메뉴명 · 요청사항 · 주소는 **잘리지 않게 줄을 바꾼다**. 길어서 한 장을 넘으면 다음 장으로 이어 그린다.
- 커팅은 프린터 드라이버 설정을 따른다(문서 끝에서 자름). 실물로 확인한다.
- 다른 OS(Linux · macOS)는 출력하지 않고 실패로 처리한다(T11과 같음). 개발 PC 확인 방법은 11장 C.

## 3. 주문서 (p.22, Q49)

### 3.1 양식

| 순서 | 내용 |
|---|---|
| (재출력일 때) | 맨 위 「[재출력] HH:mm」 (출력 시각) |
| 1 | 「픽업오더 주문서 (주방 / 바리스타용)」 |
| 2 | 픽업번호 「#108」 (가장 크게, 굵게) |
| 3 | 주문번호 · 주문일시(YYYY-MM-DD HH:mm) · 주문자(가린 이름 + 끝 4자리, 예: 박*준 (1234)) · 픽업예정(HH:mm 또는 「지금」) |
| 4 | 요청사항: 있으면 굵게 강조해 출력, 없으면 그 줄을 출력하지 않는다 |
| 5 | 메뉴: 「메뉴명 × 수량」, 옵션은 아랫줄마다 「ㄴ 옵션」. 메뉴 사이 구분선 |

- 출력물의 옵션은 한 줄에 하나(화면의 콤마 한 줄과 일부러 다름, Q49 ②).
- 주문자 · 픽업예정 값은 화면(T04 카드 · T05 팝업)과 같은 함수로 만든다.

### 3.2 언제 뽑나

| 경우 | 프린터 | 「[재출력]」 |
|---|---|---|
| **자동**: 이 PC에서 [주문접수]가 서버에서 성공했을 때(본 창 · 위젯 · 요약 팝업 모두, Q13 · Q33) | 「주문서」 체크된 슬롯 **모두** (Q45 ①) | 안 찍음 |
| 요약 팝업 · 주문내역 상세의 [주문서 인쇄], 이미 출력된 주문 | 「주문서」 체크된 슬롯 모두 | **찍음** + 시각 |
| 출력 실패 띠의 [다시 인쇄], 「미출력」 꼬리표가 붙은 주문의 [주문서 인쇄] | **실패한 슬롯만** (Q47) | 안 찍음(첫 출력과 같음) |

- 자동 출력은 같은 주문에 **한 번만**: T03의 `onAccepted`는 이 PC에서 서버 성공 뒤 한 번만 신호를 내므로 그것만 듣는다. 다른 PC에서 접수된 주문은 뽑지 않는다(Q13).
- 「주문서」 체크된 슬롯이 하나도 없으면 자동 출력은 조용히 건너뛴다(T11 프린터설정 탭의 안내가 이미 있음). [주문서 인쇄]는 「주문서를 출력할 프린터가 없습니다.」 토스트.
- [주문서 인쇄]는 접수대기 · 취소 주문에서 막힌다(Q27, T05 · T07 표 그대로). 제조중 · 제조완료 · 픽업완료에서 켠다.
- "이미 출력됨 / 미출력" 기록은 이 PC의 메모리에만 둔다. 프로그램을 다시 켜면 「미출력」 꼬리표는 사라지고, 그 뒤 [주문서 인쇄]는 「[재출력]」을 찍는다(11장 D).

## 4. 영수증 (p.23, Q50)

### 4.1 흐름

1. 요약 팝업 · 주문내역 상세의 [영수증 인쇄]를 누르면 **미리보기 팝업**이 뜬다(Q50 ②). 주문 상세(결제정보 포함)를 서버에서 읽어 온다.
2. 미리보기 팝업: 영수증 모양 그대로 + [영수증 인쇄] [닫기]. [영수증 인쇄]는 「영수증」 체크된 슬롯 중 **번호가 가장 앞선 한 대**로만 낸다(Q45 ①). 성공하면 「영수증을 출력했습니다.」 토스트, 팝업은 닫는다.
3. 「영수증」 체크된 슬롯이 없으면 [영수증 인쇄] 버튼이 막힌다(요약 팝업 · 상세 · 미리보기 모두). 상태와 상관없이 접수대기에서도 뽑을 수 있다(Q27).
4. 상세 읽기 실패: 미리보기 팝업 안에 「영수증 정보를 불러오지 못했습니다. [다시 시도]」.
5. 영수증 출력 실패: 팝업을 닫지 않고 「영수증을 출력하지 못했습니다. (슬롯 N 프린터이름: 이유)」를 팝업 안에 보인다. 빨간 띠 · 「미출력」 · 경고음은 주문서에만 쓴다(Q47은 주문서 실패 규칙).

### 4.2 양식

| 순서 | 내용 |
|---|---|
| 0 | 제목 「영수증」, 취소 주문은 「취소 영수증」 |
| 1 | 점포명 · 전화번호 · 주소 · 대표자 · 사업자번호 · 판매일자(결제 시각) · 주문번호 |
| 2 | 메뉴: 메뉴명 · 수량 · 금액, 옵션은 아랫줄 「ㄴ 옵션 금액」 / 주문금액 · 할인금액(종류별) · 결제금액 · 과세금액 · 부가세 |
| 3 | 결제: 카드면 카드번호(가린 값) · 거래종류 · 거래구분 · 승인번호 · 승인일시 · 매입사명. 카드가 아니면(간편결제 등) 「결제수단: 카카오페이」 · 승인번호 · 승인일시만 (Q50 ①) |

- 포인트 · 쿠폰으로 전액 결제: 결제 줄 대신 「결제 금액 0원」과 할인 내역만(Q50 ①).
- 취소 영수증: 금액을 모두 마이너스로(Q50 ③).
- 과세금액 · 부가세는 서버가 준 값을 그대로 찍는다(앱이 계산하지 않음).

## 5. 출력 실패 (Q47 · Q44)

| 항목 | 처리 |
|---|---|
| 접수 | 그대로. 출력 실패로 접수를 되돌리거나 막지 않는다 |
| 경고음 | T06의 경고음 한 번 (Q44) |
| 빨간 띠 | 화면 아래 배너 쌓기(T04 `BottomBanners`): 「주문서를 출력하지 못했습니다. (슬롯 1 SEWOO: 이유) [다시 인쇄] [×]」. 누를 때까지 남는다. 주문마다 띠 하나, 실패한 슬롯만 적는다 |
| 카드 | 주문접수 화면 카드(T04) · 위젯 카드(T06)에 「미출력」 꼬리표. 다시 인쇄에 성공하면 지운다 |
| [다시 인쇄] | 실패한 슬롯에만 다시 낸다. 성공하면 띠를 지우고, 또 실패하면 띠 내용을 바꾼다 |
| 결과를 모를 때 | 「출력 결과를 확인할 수 없습니다.」로 같은 띠 (11장 B) |

- "실패"의 뜻은 11장 B. 드라이버 방식이라 용지 없음처럼 프린터 안의 문제는 알 수 없는 경우가 있다.
- 이유 문구(Rust가 돌려줌, 입력값 · 경로 없이): 「프린터를 찾을 수 없음」 · 「인쇄를 시작하지 못함」 · 「이 PC에서는 출력할 수 없음」 등.

## 6. 데이터 (가정, 백엔드 협의 전)

- 주문서: T03 주문 데이터(`Order`)로 충분하다. 옵션은 표시용 이름 문자열을 그대로 쓴다.
- 영수증: T07 주문 상세(`HistoryOrder`)에 아래를 더한다고 가정한다. 백엔드 요청 문서 7.2 #4(결제정보 · 영수증 항목)에 가정한 모양을 덧붙인다.
  - 결제: 과세금액 · 부가세, 승인번호 · 승인일시, 카드면 가린 카드번호 · 거래종류(신용 · 체크) · 거래구분(일시불 · 할부 N개월) · 매입사명. 카드번호는 서버가 가려서 준다(앱이 원번호를 받지 않음).
  - 점포 영수증 정보: 점포명 · 전화번호 · 주소 · 대표자 · 사업자번호. 새 조회 하나로 가정(로그인 뒤 한 번 읽고, 영수증 미리보기 때 없으면 다시 읽음).
- 모의 서버: 카드 결제 · 간편결제 · 전액 할인 · 취소 주문 예시를 하나씩 준다.
- 요청 10초 제한.

## 9. 테스트 전략

- 순수 함수: 주문서 줄 목록(요청사항 있음 · 없음, 옵션 줄, 재출력 머리), 영수증 줄 목록(카드 · 간편결제 · 전액 할인 · 취소 마이너스), 58 / 80mm 줄바꿈.
- 화면: 자동 출력(체크 슬롯 모두, 한 번만, 다른 PC 접수는 안 뽑음, 체크 슬롯 없음), [주문서 인쇄] 상태별 켜짐 · 재출력 표시, 실패 → 경고음 · 띠 · 미출력 · [다시 인쇄] 실패 슬롯만, 영수증 미리보기 · 앞선 슬롯 한 대 · 체크 없으면 막힘 · 상세 실패.
- Rust: 줄바꿈 계산(폭 안에 들어가게 자르기)을 OS와 상관없이 테스트.

## 10. 완료 기준

1. 접수하면 「주문서」 체크된 슬롯마다 한 장씩 나오고, 같은 주문의 자동 출력은 반복되지 않는다 (테스트 + Windows 실물).
2. [주문서 인쇄]로 다시 뽑으면 「[재출력]」과 시각이 찍히고, 실패 뒤 [다시 인쇄]에는 찍히지 않는다 (테스트).
3. 요청사항이 없으면 그 줄이 없다. 옵션은 한 줄에 하나 (테스트 + 실물).
4. [영수증 인쇄]는 미리보기를 거쳐 앞선 슬롯 한 대로만 나오고, 취소 주문은 「취소 영수증」(마이너스), 간편결제 · 전액 할인 양식이 맞다. 「영수증」 체크가 없으면 눌리지 않는다 (테스트).
5. 출력에 실패해도 접수는 되고, 경고음 · 빨간 띠 · 「미출력」이 나오며 [다시 인쇄]는 실패한 슬롯에만 낸다 (테스트).
6. 실물 확인(한글 · 줄바꿈 · 크기 · 커팅 · 긴 글)은 체크리스트로 요청한다 (SEWOO SLK-TS100, 2026-11-20 예정).
7. ① lint · typecheck · format · test · build · Rust 검사 통과, ② · ③ 리뷰 완료.
