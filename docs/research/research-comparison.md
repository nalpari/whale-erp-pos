# 리서치 문서 비교: 기존(Antigravity) vs 신규(Claude)

- **작성일**: 2026-11-12
- **비교 대상**
  - 기존: `docs/research/coffee-smart-order-admin-system.md` (Antigravity로 수집, 업계 전반)
  - 신규: `docs/research/store-order-receiver-tech-research.md` (Claude로 수집, 이 프로젝트 범위, 1차 출처 기반)
- **목적**: 두 문서의 범위·신뢰도·내용 차이를 정리하고, 기존 문서에서 계속 쓸 부분과 버릴 부분을 구분한다.

---

## 1. 한눈에 비교

| 항목 | 기존 문서 (Antigravity) | 신규 문서 (Claude) |
|---|---|---|
| 범위 | 업계 전반: 본사·가맹점·POS·KDS·DID·컵 라벨·재고/BOM·정산·배달앱 연동 | 이 프로젝트만: 매장 PC 주문접수 프로그램, 주문서 출력, 실시간 수신, 배포·업데이트·서명 |
| 출처 | 없음 (벤치마크 업체 이름만 언급) | 공식 문서·표준·제조사 매뉴얼 링크 약 180개. 확인 못 한 항목은 "확인 불가"로 표시 |
| 수치 | 근거 없는 수치 다수 (피크 65%, 테이크아웃 70~80%, 85dB, 지연 목표 1.5초/1.0초/0.8초 등) | 출처가 있는 수치만 사용 (지원 종료일, 타임아웃 기본값, 인증서 유효기간 등) |
| 결론 방식 | 아키텍처·로드맵을 권장안으로 제시 | 사실과 장단점만 정리, 결정은 하지 않음 |

## 2. 주제별 비교

| 주제 | 기존 문서 | 신규 문서 | 판정 |
|---|---|---|---|
| Windows·실행 환경 | 다루지 않음 | Win7·POSReady 7·Win10·IoT LTSC 지원 종료일, 도구별 최소 Windows 버전, Tauri 2.12의 Win7 지원 중단, Win7 선택지(2A장) | 신규만 있음 |
| Tauri·Next.js·자동 업데이트·코드 서명 | 다루지 않음 | 업데이터 서명 필수·키 분실 위험, 설치 중 앱 종료, NSIS 설치 범위와 관리자 권한, Next.js 정적 내보내기 제약, SmartScreen·Artifact Signing | 신규만 있음 |
| ESC/POS 명령 | `GS V 66 0`을 "Gap 센서 위치까지 자동 피드"로 설명 | "이송 후 부분 절단"이며 제조사·모델마다 동작이 다름 (Epson·Bixolon 매뉴얼) | **기존 문서 오류** |
| 한글 출력 | "CP949 또는 UTF-8 전환 커맨드 세팅" | 한국 모델 내장 글꼴(KS C 5601), Epson Kanji 모드, 래스터(이미지) 출력 대안. UTF-8 파라미터는 확인 불가 | 기존 문서는 단순화·부정확 |
| 프린터 공유 | 다루지 않음 | COM 포트 독점(Microsoft), Epson LAN 9100 출력 연결 1개, 스풀러 경로는 공유 가능 | 신규만 있음 |
| 실시간 통신 | WebSocket(매장 LAN) + MQTT/WebSocket(클라우드) + SSE + FCM 혼합 구성을 권장 | NAT 제약, ALB·nginx 60초 타임아웃, WebSocket·SSE에 ack 없음, Redis Pub/Sub at-most-once, AWS IoT Core 한계 등 방식별 사실 비교 | 기존은 근거 없는 권장, 신규는 근거 기반 비교 |
| 신뢰성 패턴 | 멱등키 헤더 강제 | 멱등키가 아직 IETF 초안(draft-08)이라는 점, at-least-once + 중복 제거, 앱 수준 ack 필요 | 신규가 더 정확 |
| 분할 결제 | 2PC 또는 Saga | 다루지 않음 (범위 밖) | 기존의 2PC 언급은 외부 PG·기프티콘 시스템에 적용 불가 |
| 주문 상태 흐름(FSM) | 있음 | 없음 (범위 밖) | 기존만 있음 (빠진 경로 있음: 접수 전 고객 취소, 노쇼, 부분 환불) |
| 메뉴·옵션 구조 | 있음 (트리 + JSON 스키마) | 없음 (범위 밖) | 기존만 있음 (트리와 JSON 불일치, 수량형 옵션 미표현) |
| 피크타임 운영 | 대기시간 수식, 주문 일시 중지, 지연 추가, 품절 전파 | 없음 | 기존만 있음 (수식과 구간표 불일치) |
| 오프라인 대응 | 로컬 SQLite, VAN 오프라인 승인, 지수 백오프 동기화 | 없음 (범위 밖) | 이 프로젝트는 결제를 다루지 않아 대부분 해당 없음 |
| 국내 서비스 벤치마크 | 업체 이름 나열 | 배민·쿠팡이츠·요기요·토스 공식 최소 사양 조사 (대부분 확인 불가) | 둘 다 실질 정보 부족 |

## 3. 기존 문서 활용 가이드

### 계속 참고할 부분

| 위치 | 내용 | 활용처 | 주의 |
|---|---|---|---|
| 3.1 주문 라이프사이클 FSM | 상태와 전이 조건 | 백엔드와 상태 이름·전이를 합의할 때 출발점 | 접수 전 고객 취소, 노쇼, 부분 환불 경로 보완 필요. 재고 차감·복구 시점 모순 |
| 3.3 피크타임 제어 아이디어 | 주문 일시 중지, 지연 시간 일괄 추가, 품절 처리 | 파일럿 범위에 넣을 기능 후보 목록 | 대기시간 수식과 구간표가 서로 맞지 않음 |
| 4장 메뉴·옵션 구조 | 옵션 그룹 트리 | 주문서에 옵션을 어떻게 찍을지 정할 때 참고 | 트리와 JSON의 필수 여부 불일치, 수량형 옵션 미표현 |

### 버려도 되는 부분

| 위치 | 이유 |
|---|---|
| 1~2장 (업계 개요, 3계층 구조, RBAC, 클라우드-엣지 토폴로지) | 이 프로젝트 범위보다 훨씬 넓고, 출처 없는 수치 포함 |
| 3.2 통신 프로토콜 권장안 | 근거 없는 혼합 구성. `docs/proposals/realtime-delivery-options.md`와 신규 문서 6장으로 대체 |
| 5.3 ESC/POS 라벨 프린터 | 명령 설명 오류. 신규 문서 5장으로 대체 |
| 5.1·5.2·5.4 KDS·DID·하드웨어 구성 | 이 프로젝트 범위 밖 |
| 6~8장 (BOM·재고, 결제·정산, 옴니채널) | 이 프로젝트 범위 밖 |
| 9장 로드맵·체크리스트 | 일정이 이미 지났고 이 프로젝트 범위·일정과 다름. 지연 목표치 근거 없음 |

## 4. 신규 문서에 아직 없는 것 (스펙 단계 과제)

| 주제 | 비고 |
|---|---|
| 주문서 양식 | 어떤 항목을 어떤 순서·크기로 찍을지 (옵션, 요청사항, 주문번호 등) |
| 피크타임 운영 기능 | 일시 중지·지연·품절을 파일럿 범위에 넣을지 (백엔드·앱 팀 협의 필요) |
| 개인정보 처리 | 주문 데이터에 포함되는 고객 정보 최소화 기준 |
| 화면 UX 기준 | 알림음, 글씨 크기, 터치 대상 크기 등 매장 환경 기준 |
